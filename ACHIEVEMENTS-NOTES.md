# Достижения: заметки для документации (ACHIEVEMENTS-NOTES.md)

Статус: сделано 2026-10-22. Значки наград в профиле. Принцип: **никаких хуков в чужой код**. Достижения вычисляются на чтение из таблиц, которые уже есть; таблица `achievements` только помнит, что награда получена и когда.

## Бэкенд

- Пакет `backend/internal/achievements`:
  - `catalog.go`: каталог `Catalog` (47 достижений в 9 категориях), `Def{ID, Category, Tier, Metric, Target}`; ступени `bronze/silver/gold`; метрики (`MGames`, `MRating`, ...).
  - `thresholds.go`: **все пороги одним местом** (10/100/500 партий, 3/5/10 ботов, рейтинги 1400/1600/1800/2000, `MinRatedGames = 5`, `MinPuzzleAttempts = 10`, `AccuracyHigh = 90`, `LongGameMoves = 40` и т. д.) и сроки кэша.
  - `evaluate.go`: `Facts` (счётчики из store + серия дней + разделы уроков), `Evaluate(Facts) []Progress` (значение, цель, выполнено; прогресс обрезан целью).
  - `service.go`: `Service` и маршруты. Оценка запускается **по запросу** с кэшем на человека (`ProfileMaxAge` 5 с для вкладки профиля, `PollMaxAge` 15 с для уведомления, `PublicMaxAge` 60 с для чужого профиля); одна оценка человека одновременно (мьютекс записи кэша), кэш до 4096 человек. Хуков в `play`, `puzzles`, `lessons` и др. нет.
- Тексты (названия и описания) **на сайте**, не в Go: `web/src/i18n/{ru,en}/achievements.js`; сервер отдаёт только id. Тест Go `TestTextsExistOnTheSite` читает эти словари и проверяет, что у каждого id каталога есть `name` и `desc` на обоих языках, а у каждой категории подпись.
- `store/achievements.go`: `AchievementFacts` (4 запроса по индексам с id человека: сгруппированные партии по сторонам, «против бота», результату, окончанию, длине, «рейтинговая», «заочная» через `JSON_EXTRACT` по документу партии; один запрос со скалярными подзапросами для остального; id пройденных уроков), `AccuracyReviews`, `BrilliantReviews` (поиск `JSON_SEARCH` внутри MySQL, отчёты на сервер не читаются), `Achievements`, `AddAchievements` (`INSERT IGNORE`, возвращает только новые), `MarkAchievementsSeen`.
- Миграция `0027_achievements.sql`: `achievements(user_id, ach_key, unlocked_at, seen)`, ключ `(user_id, ach_key)` (то есть уникальность), каскад от `users`. Колонка названа `ach_key`, потому что `key` в MySQL зарезервировано.
- `MergeUsers` (store/users.go): одна вставка, достижения гостя объединяются с аккаунтом, дата берётся ранняя, `seen` по наибольшему.
- API: `GET /api/achievements` (вошедший, гость подходит; `?poll=1` для уведомления) → `{items:[{id, category, tier, target, progress, unlocked, unlockedAt, seen}], unlocked, total, unseen:[id...]}`; `POST /api/achievements/seen` `{ids:[...]}` (пусто: все); `GET /api/users/{id}/achievements` (публично: только полученные `{id, category, tier, unlockedAt}`, счётчик, без `seen` и прогресса; 404 для неизвестного). В `main.go` маршрут `/api/users/{id}/achievements` зарегистрирован отдельно и перекрывает `/api/users/` (профили).

## Что чем считается

- **Партии** (завершённые онлайн-партии с результатом, с людьми и ботами; партии против движка в браузере на сервере не сохраняются): `first_game`, `games_10/100/500`, `first_human_win`, `rated_win` (победа в партии с флагом `rated` у человека), `mate_win` (`termination = checkmate`), `time_win` (`timeout`), `first_draw`, `long_game` (40 полных ходов: 79 полуходов и больше).
- **Боты** (`bot_progress.wins > 0`): `first_bot_win`, `bots_3/5/10`, `beat_max` (бот `max`).
- **Рейтинг**: `rating_1400/1600/1800/2000` по лучшему рейтингу среди категорий (пуля, блиц, рапид и дуэль), категория считается после 5 партий (иначе первая победа поднимает новичка на сотни пунктов), `first_duel` (дуэль сыграна).
- **Задачи**: `first_puzzle`, `puzzles_100/500` (решённые первые попытки из `puzzle_attempts`), `puzzle_rating_1500/1800` (после 10 попыток), `points_streak_5/20` (`puzzle_points.best_streak`), `rush_20` (лучший штурм), `duel_win`.
- **Разбор**: `first_review`, `reviews_10`, `accuracy_90` (точность своей стороны не ниже 90 в партии не короче 10 ходов; сторона определяется по имени в PGN так же, как в статистике, не определилась: не считается), `brilliant_move` (ход класса `brilliant` на своей стороне по чётности индекса хода).
- **Дебюты**: `first_repertoire`, `rep_moves_50/200` (все ходы всех репозиториев), `learned_line` (5 своих ходов дошли до конца лесенки, `store.LearnedBox`).
- **Уроки**: `first_lesson`, `lesson_section` (раздел целиком), `all_lessons` (цель = число уроков курса из библиотеки, не зашита).
- **Сообщество**: `first_friend`, `friends_10`, `first_post` (не удалённое сообщение форума), `corr_game` (заочная партия доиграна).
- **Серии**: `streak_3/7/30` (лучшая серия дней с задачами, `stats.BuildStreak`, день UTC).

## Дорогие поиски

Точность и блестящие ходы читают таблицу `analyses`. Они запускаются, только если достижение ещё не получено и число разборов человека изменилось с прошлого безуспешного поиска (число помнится в памяти сервера; после перезапуска один повтор). Ищется в последних 100 разборах (`ReviewScanLimit`).

## Ограничения

- Дата получения: когда награда **впервые засчитана** сервером, а не когда это случилось на самом деле. Достижения старых аккаунтов засчитываются при первом открытии (все с одной датой), уведомление при этом одно общее.
- Новая награда появляется после ближайшей оценки: до 15 с на сервере плюс интервал опроса (до минуты, после смены страницы около 15 с).
- Награда, однажды полученная, не отбирается (удалили друга, сменился рейтинг).
- «Партии» не включают партии против движка в браузере и «Другие шахматы».
- Победа с рейтингом, мат и время считаются по полям документа партии (`rated`, `termination`); партии, сохранённые до появления этих полей, могут их не иметь.
- `accuracy_90` и `brilliant_move` не считаются, если по имени в PGN не определить сторону.

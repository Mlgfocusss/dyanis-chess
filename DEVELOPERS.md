# Dyanis Chess: подробное описание для разработчиков

Полное описание: запуск, устройство сайта и движка, команды, структура. Краткий обзор для знакомства: [`README.md`](./README.md); план и журнал работ: [`WEB-PLAN.md`](./WEB-PLAN.md).

Движок написан с нуля, сам движок на Go не использует сторонних библиотек.
Нейросеть обучена на собственных данных: партии генерировал сам движок.

## Что умеет

- **Играть** — против вас в терминале или в браузере.
- **Разбирать партии** — загрузить PGN и получить оценку каждого хода,
  ошибки и зевки, лучшие продолжения и точность игроков (`backend/cmd/analyze`).
- **Сайт** (Docker: `docker compose up --build`, http://localhost:8080): вход гостем или через Google, разбор партий со значками ходов (от «зевка» до «блестящего»), игра с другом по ссылке, игра с ботами (10 ботов с рейтингами), игра против движка, задачи с рейтингом, профиль. Подробнее ниже и в `WEB-PLAN.md`.
- **Работать как UCI-движок** в Arena, CuteChess, Lichess-bot и т. п.
- **Меряться силами с другими движками** — встроенный инструмент матчей.

## Сила игры

Ориентир — матчи против Stockfish 19 с ограничением силы (`UCI_Elo`), один
поток, 500 мс на ход:

| Версия | Примерно по шкале `UCI_Elo` |
|---|---|
| ручная оценка позиции | ≈ 2700 |
| первая NNUE-сеть | ≈ 2800 |
| **текущая сеть** (`net-kingf-m4.bin`), измерено 2026-10-17 | **≈ 2910** |

Текущая версия против Stockfish 19, 500 мс на ход, один поток, по 100 пар (200 партий) на уровень:

| `UCI_Elo` Stockfish | счёт (наш движок) | Elo (мы − SF) | оценка |
|---|---|---|---|
| 2900 | +74 =70 −56 (54,5%) | +31 ± 38 | ≈ 2931 |
| 3050 | +9 =95 −96 (28,2%) | −162 ± 35 | ≈ 2888 |

Оба уровня согласуются, итог **≈ 2910 по шкале `UCI_Elo`** (погрешность около ±30). Прирост сетей против первой NNUE оказался меньше, чем
по цепочке матчей между версиями (+110 вместо +250): цепочка суммирует погрешности, абсолютное измерение надёжнее. Шкала `UCI_Elo` откалибрована на длинном
контроле времени и не равна рейтингу FIDE или CCRL — это ориентир, а не
рейтинг. Как мерили и что пробовали — в [`engine/plan.md`](./engine/plan.md) и
[`engine/NNUE.md`](./engine/NNUE.md).

## Что внутри

- Битборды, magic bitboards, легальная генерация ходов (проверена perft).
- Поиск: итеративное углубление, aspiration windows, PVS, null-move, LMR,
  razoring, futility, LMP, reverse futility, SEE, quiescence, таблица
  транспозиций, Lazy SMP на нескольких потоках.
- Оценка двух видов:
  - **ручная** — материал, таблицы клеток, подвижность, пешки, безопасность
    короля, пара слонов; веса подобраны Texel-тюнингом;
  - **NNUE** — сеть 768 входов с корзинами по положению короля → 256 нейронов
    (SCReLU) → 8 выходов по числу фигур. Обучение в PyTorch (`engine/train/`),
    вывод в Go (`engine/internal/nnue`), при сборке с SIMD быстрее.
- Книги дебютов в формате Polyglot (`engine/assets/`).
- Разбор партий: чтение PGN (`backend/internal/pgn`) и оценка ходов
  (`backend/internal/analysis`).
- Инструменты разработчика: матчи между версиями со статистикой по парам
  и SPRT, SPSA-подбор параметров поиска, генерация данных для сети,
  профилировщик.

## Требования

- [Go](https://go.dev/dl/) 1.22 или новее. Для быстрой версии с SIMD — Go 1.26+
  и процессор с AVX2.
- Для веб-версии — Node.js и npm.
- Для обучения сети — Python 3 с PyTorch и видеокарта (необязательно).

## Быстрый старт

Команды движка выполняются из папки `engine/` (`cd engine`). Нейросеть лежит там же:
`engine/net-kingf-m4.bin`. Без флага `-evalfile` движок играет на ручной оценке.

```bash
cd engine

# Сыграть против движка (ходы: e4, Nf3, O-O или e2e4)
go run ./cmd/cli -play -movetime 1000 -evalfile net-kingf-m4.bin

# Только на ручной оценке, фиксированная глубина
go run ./cmd/cli -play -depth 4

# Запустить все тесты
go test ./...                # из engine/ — тесты движка; из корня — всё вместе
```

Для постоянного использования соберите бинарник. Версия с SIMD заметно быстрее
для сети:

```bash
GOEXPERIMENT=simd go build -o dyanis ./cmd/cli       # Linux / macOS
go build -o dyanis.exe ./cmd/cli                       # Windows, без SIMD
```
```powershell
$env:GOEXPERIMENT="simd"; go build -o dyanis.exe ./cmd/cli    # Windows, с SIMD
```

## Разбор партии

```bash
go run ./backend/cmd/analyze -pgn game.pgn -evalfile engine/net-kingf-m4.bin -movetime 300
```

Печатает для каждого хода оценку (с точки зрения белых), вероятность победы,
класс хода (лучший, отличный, хороший, неточность, ошибка, зевок), потерю и
лучший ход, если он другой; в конце — точность каждого игрока и ключевые
моменты. Точность считается так, чтобы решающая ошибка (например, зевок ферзя)
не терялась среди хороших ходов; это собственная модель проекта, а не копия
расчёта chess.com, поэтому цифры у разных сайтов не совпадают. `-depth N` вместо времени даёт воспроизводимый результат,
`-json` — вывод для программ, `-game N` выбирает партию из файла с
несколькими.

**Дебюты.** Перед таблицей печатается название дебюта и код ECO (например,
`C55 Italian Game: Two Knights Defense`), а ходы теории получают класс `book`.
Ход считается теоретическим, пока позиция лежит на какой-либо линии справочника
(перестановки ходов тоже находятся, ключ — хеш позиции); первая позиция вне линий
закрывает книгу навсегда. Книжные ходы не входят в точность: иначе короткая партия
с длинной теорией выглядела бы безупречной. Если все ходы игрока книжные, его
точность 100. Для партий с нестандартной начальной позицией книга не применяется.
Справочник — [lichess-org/chess-openings](https://github.com/lichess-org/chess-openings)
(CC0), файлы лежат в `backend/internal/eco/data/`.

Для проверки в `backend/testdata/games/` лежат пять реальных партий.

Файл PGN можно скачать, например, из архива партий на chess.com или lichess.
Понимаются комментарии, варианты (пропускаются), часы `[%clk]` и партии с
нестандартной начальной позицией.

## Использование в шахматных программах (UCI)

```bash
cd engine
go run ./cmd/cli -uci -evalfile net-kingf-m4.bin
```

В Arena и CuteChess укажите путь к собранному бинарнику, в «Arguments» —
`-uci -evalfile <путь к net-kingf-m4.bin>`. Сеть можно подключить и из самой
программы: UCI-опция `EvalFile`.

Поддерживаются команды `uci`, `isready`, `ucinewgame`, `position`, `setoption`,
`go` (`depth`, `movetime`, `wtime`/`btime`/`winc`/`binc`/`movestogo`) и `quit`.
Команды `stop`, `infinite` и `ponder` не реализованы — поиск всегда идёт до
своего лимита. Опции: `Threads` (число потоков), `Hash` (размер хеш-таблицы в
МБ, по умолчанию 16), `EvalFile` (файл сети), а также параметры поиска
(описаны в [`engine/TECHNICAL.md`](./engine/TECHNICAL.md), раздел про SPSA).

По умолчанию подключается книга `assets/gm2001.bin`. Несколько книг можно
цепочкой по приоритету:

```bash
go run ./cmd/cli -uci -book "assets/gm2001.bin,assets/komodo.bin,assets/performance.bin"
```

`-book ""` отключает книгу.

> Управление временем по часам реализовано базово и не проверялось в
> реальных партиях на сервере. Это слабое место.

## Параметры командной строки (`engine/cmd/cli`)

| Флаг | Что делает |
|---|---|
| `-play` | интерактивная партия в терминале |
| `-uci` | режим UCI поверх stdin/stdout |
| `-evalfile файл` | нейросеть; без флага — ручная оценка |
| `-fen "..."` | начальная позиция |
| `-perft N` | подсчёт ходов до глубины N |
| `-depth N` | глубина поиска |
| `-movetime мс` | время на ход (нужно для многопоточности) |
| `-threads N` | число потоков поиска (Lazy SMP) |
| `-book файлы` | книги через запятую; `-book ""` — без книги |

## Игра в браузере

Движок собирается в WebAssembly и работает прямо на странице, в отдельном
Web Worker'е. Сейчас в браузере играет **ручная оценка**, без нейросети
(SIMD в WebAssembly для Go недоступен; нейросеть будет работать на сервере
сайта).

```bash
# 1. Собрать wasm
cd engine
GOOS=js GOARCH=wasm go build -o cmd/wasm/dyanis.wasm ./cmd/wasm
```
```powershell
# то же в PowerShell
cd engine
$env:GOOS="js"; $env:GOARCH="wasm"; go build -o cmd/wasm/dyanis.wasm ./cmd/wasm
```
```bash
# 2. Скопировать файлы для веб-интерфейса (в Docker это делает сборка сама)
cp cmd/wasm/dyanis.wasm cmd/wasm/wasm_exec.js ../web/public/wasm/
cp assets/*.bin ../web/public/assets/

# 3. Запустить
cd ../web
npm install
npm run dev
```

Откройте адрес, который напечатает Vite. В интерфейсе есть поле FEN:
«Загрузить FEN» ставит произвольную позицию, «Скопировать текущий FEN»
сохраняет текущую.

Страница «Игра с ботом» занимает всю ширину окна, доска подгоняется под высоту экрана. Панель
управления стоит у правого края; переключатель «Доска сбоку / Доска по центру» (или пункт в
«Настройки → Доска и фигуры») ставит доску посередине, а партию и статус переносит влево. Есть кнопка
**«Сдаться»** (с подтверждением) и глубина от 1 до 30 числом. Глубина без ограничения по времени на
больших значениях считает долго; идущий поиск прерывается кнопками «Сдаться», «Новая партия» и
загрузкой FEN (воркер перезапускается, книга возвращается сама).

После конца партии над доской появляется карточка итогов (результат и причина, игроки, число ходов) с
кнопками «Смотреть отчёт» (партия уходит на разбор), «Новая партия» и «Реванш».

## Сайт: разбор партии в браузере

### Запуск через Docker (основной способ)

```bash
cp .env.example .env          # один раз; впишите свои пароли (буквы и цифры)
docker compose up --build     # http://localhost:8080
```

Три контейнера: `db` (MySQL 8.4, данные в томе `dbdata`), `server` (Go: движок, сеть
`engine/net-kingf-m4.bin`, API) и `web` (nginx: React и прокси `/api`). Наружу открыт только `web`
(порт `WEB_PORT`, по умолчанию 8080); MySQL доступен для SQL-клиента на `127.0.0.1:3317`
(`DB_PORT`). Схема базы создаётся сама при запуске сервера (миграции в
`backend/internal/store/migrations/`). Готовые разборы лежат в базе: ссылка вида
`http://localhost:8080/#review/<id>` открывает разбор и после перезапуска. `docker compose down`
данные сохраняет, `docker compose down -v` удаляет вместе с томом.

Тесты хранилища на настоящей базе (без переменной они пропускаются):
`$env:DYANIS_TEST_DSN="dyanis:ПАРОЛЬ@tcp(127.0.0.1:3317)/dyanis"; go test ./backend/internal/store`.

### Вход: гость и Google

Без входа сайт работает (разбор, бот). Меню → «Войти»: можно **продолжить как гость** (один клик, без
регистрации) или **войти через Google**. Вошедший пользователь получает «Профиль» (вкладка «Партии»: все его разборы с
точностью и дебютом, удаление) и настройки доски, которые следуют за ним на другое устройство. Гость,
позже вошедший через Google, не теряет партии. Для входа нужна база (`-dsn`), в Docker она есть.

Вход через Google необязателен. Чтобы включить, в [Google Cloud Console](https://console.cloud.google.com/)
создайте «Идентификатор клиента OAuth» (тип «Веб-приложение»), в «Разрешённые URI перенаправления»
добавьте `http://localhost:8080/api/auth/google/callback` (для своего домена: `https://домен/api/auth/google/callback`)
и впишите ключи в `.env` (в git он не попадает):

```
PUBLIC_URL=http://localhost:8080
GOOGLE_CLIENT_ID=...apps.googleusercontent.com
GOOGLE_CLIENT_SECRET=...
```

Затем `docker compose up -d server`. Пока приложение на экране согласия имеет статус «Тестирование»,
входить могут только адреса из списка «Тестовые пользователи». Без ключей кнопка Google неактивна, а
гости работают. Пароли и токены Google сайт не хранит; сессия лежит в cookie `HttpOnly`, в базе только
хеш её токена. Подробности — в `WEB-PLAN.md`, раздел «Аккаунты».

Название дебюта показывается и во время партии (онлайн, с ботом, против движка) по справочнику ECO, с пометкой «теория».
В онлайн-партии между людьми есть чат. Значки ходов можно заменить своими картинками: положить файлы
`brilliant`, `great`, `best`, `excellent`, `good`, `book`, `miss`, `inaccuracy`, `mistake`, `blunder` в `web/src/review/badges/`
(см. `README.md` в этой папке) и пересобрать сайт.

### Игра с ботами

«Играть → Играть с ботами»: десять ботов от новичка (Миша, 400) до пика движка (Максимум, 2900), среди них
Дионис Самусенко (спортсмены, 1800). У каждого свой рейтинг (по шкале самого движка, не FIDE: измерен
партиями ботов друг с другом, `go run ./backend/cmd/botladder`), описание и реплики. Можно выбрать цвет и
часы. За первую победу над ботом начисляются очки, бот отмечается побеждённым; прогресс виден на странице
ботов и в профиле. Партия идёт как онлайн-партия: сдача, ничья (бот принимает, если он явно хуже), реванш,
разбор на месте. Рейтинги пересчитаны 2026-10-16: от 900 и выше метки совпадают с измеренной силой (Дионис 1800, измерено 1784), ниже шкала условная. Миша не знает, что такое мат (не ищет его и не боится). Подробности и методика рейтингов в `WEB-PLAN.md`.

### Таблица лидеров, статистика, настройки аккаунта, дебюты по-русски

- **Профиль** («Настройки → Профиль»): имя, фамилия, местоположение, страна (список из 249 стран с поиском), «Обо мне» и аватар (12 готовых, буква имени или фото Google). Данные видны в публичном профиле `#user/<id>`; страна — в таблице лидеров с фильтром по стране. API: `PUT /api/me/profile`, `GET /api/countries`.
- **Тема** («Настройки → Интерфейс → Тема»): тёмная, светлая или как в системе. В CSS компонентов используйте только токены из `web/src/index.css`: зашитый цвет сломает светлую тему (это проверяет тест).
- **Уроки** (`#lessons`): 35 уроков в 5 разделах (основы, тактика, дебютные принципы, эндшпиль, стратегия) с упражнениями на доске и сохранением прогресса. Тексты и позиции лежат JSON-файлами в `backend/internal/lessons/content/`; при старте сервер проверяет весь контент, а тесты сверяют утверждения уроков движком. API: `GET /api/lessons`, `GET /api/lessons/{id}`, `POST /api/lessons/{id}/progress`. Плеер (`web/src/lessons/Player.jsx`, стили `.lp*` в `lessons.css`) устроен как на chess.com: слева доска на всю высоту окна, справа панель ровно в высоту доски (`contain: size`) с названием урока, Дионисом и его репликой, счётчиком «Шаг N из M» и большой кнопкой «Далее» внизу. Решённое упражнение само открывает следующий шаг через 1,5 с (`ADVANCE_MS`; «Назад» и «Далее» отменяют ожидание; после «Решение» и на текстовых шагах автоперехода нет). Горячие клавиши: ← → шаги, H подсказка, S показать.
- **Вкладка «Тренер»** (`#coach`): Дионис составляет план на день (задачи по слабой теме, повтор ходов, разбор партии, урок), показывает, как вы играете по разборам (фазы, ошибки, динамика), и советует, что подтянуть. Всё по правилам и вашим данным, без нейросети. API: `GET /api/trainer`.

- **Таблица лидеров** (`#leaders`, пункт меню «Играть → Таблица лидеров»): лучшие по рейтингу Glicko-2 в пуле, блице, рапиде и дуэли (от 5 партий, рейтинг не «приблизительный»). Имя ведёт на публичный профиль `#user/<id>` (рейтинги, места, партии, очки против ботов). API: `GET /api/leaderboard`, `GET /api/users/{id}`.
- **Статистика** (профиль, вкладка «Статистика»): партии, средняя точность и график разборов, решённые задачи, слабые темы, лучший штурм, дуэли, история попыток, серия дней (по UTC). API: `GET /api/stats`.
- **Настройки → Интерфейс, Профиль, Учётная запись:** размер текста, уменьшение анимации, контраст; смена имени (`PUT /api/me/profile`); выход и удаление аккаунта (`DELETE /api/me`, нужно слово «УДАЛИТЬ»).
- **Дебюты по-русски:** названия берутся из справочника lichess и переводятся словарём `backend/internal/eco/data/ru.tsv` (одна строка на компонент названия, правится вручную; нет перевода — показывается английское название).

### Разбор: тренер Дионис, три линии движка и ИИ-тренер

**Тренер Дионис** встречает на странице разбора сам (отключается в «Настройки → Игровой процесс → Анализ»): над карточкой хода коротко объясняет каждый ход и рисует красную стрелку на ответе соперника, который наказывает ошибку. Кнопка «Лучший ход» показывает ход движка вместо плохого, «Подробнее» просит развёрнутый текст у нейросети (см. ниже).

Три лучшие линии движка (MultiPV) показаны тонкими строками (оценка и ходы в одну строку с обрезкой, нажатие на оценку раскрывает линию целиком), любой ход нажимается и разыгрывается на доске. Кнопка «Подробнее» в карточке Диониса просит нейросеть объяснить ход словами: что в нём не так и чем он наказывается, что играть вместо него. Кнопки «Что нужно было сыграть» и «Как это наказывается» разыгрывают на доске линии движка (ходы считает движок, нейросеть только пишет текст по его данным).

Тренеру нужен ключ OpenRouter (`OPENROUTER_API_KEY` в `.env`, получить на https://openrouter.ai/keys); без ключа карточки тренера на сайте нет. Тренер использует только бесплатные модели и по очереди переходит к следующей, если одна занята или не отвечает (список по умолчанию в `backend/internal/coach`, свой список: `OPENROUTER_MODELS` через запятую). У ключа без кредита около 50 бесплатных запросов в день на весь сайт. Наружу уходит позиция, ход и линии движка, без имён и аккаунтов. Готовые объяснения хранятся в базе и повторно не тратят запросы; на человека 40 новых объяснений в час. Подробности в `WEB-PLAN.md`.

### Разбор: раскладка, ссылки и доска анализа (2026-10-21)

Страница разбора устроена как у chess.com: доска слева на высоту окна, справа панель ровно в высоту доски (`contain: size`, как у плеера уроков). Панель: шапка (результат, дебют, точность обоих игроков), вкладки «Разбор» и «Итог», прокручиваемая часть и неподвижный низ. «Разбор»: ход на доске и его класс, карточка Диониса (одна реплика и две маленькие кнопки), три тонкие строки линий, ветка, график оценки с точками ключевых моментов и подсветкой текущего хода, список ходов. «Итог»: точность, график, таблица ходов по классам для обоих игроков, ключевые моменты и лучшие моменты (нажатие открывает ход). Низ панели: «в начало, назад, проиграть/пауза, вперёд, в конец», «‹ Ошибка» и «Ошибка ›» (предыдущая и следующая ошибка, зевок или упущенная возможность), переворот доски, «Своя ветка» и меню «Поделиться» (ссылка, PGN, FEN, открыть позицию на доске анализа). Клавиши: стрелки, Home, End, пробел (проиграть/пауза, один ход в 1,1 с), Shift + стрелки (ошибки), F (переворот), Esc (из ветки в партию). Узкое окно (до 1220 px): панель под доской, шаги под доской; телефон (до 860 px): доска остаётся наверху при прокрутке, кнопки липнут к низу над меню. Режим «Доска в центре» работает: панель скрыта, шаги стоят под доской.

Ссылки: у готового разбора адрес `#review/<id>` (разбор хранится на сервере; «Поделиться» → «Копировать ссылку» копирует полный адрес и добавляет номер полухода: `#review/<id>/<n>` открывает разбор на этом ходу). **Доска анализа** (`#analysis`, пункт меню «Доска анализа», `review/AnalysisPage.jsx`) это та же панель без партии (`ReviewView` с `free`): свободная доска, движок показывает линии и оценивает каждый ход, позиция берётся из адреса `#analysis/<FEN с _ вместо пробелов>` или из вкладки «Загрузить» (FEN ставится на доску, PGN отправляется на разбор и открывается как разбор). Из разбора позицию можно открыть на доске анализа. Чистая логика (ключевые моменты, таблица классов, адреса, определение FEN) без зависимостей в `review/moments.js`, тесты `moments.test.js`.

**Стрелки движка и ссылка.** Три лучшие линии (MultiPV) рисуются на доске стрелками первого хода (`review/arrows.js`: выбор стрелок, толщина и прозрачность по номеру линии и потере вероятности выигрыша, геометрия; `components/ArrowLayer.jsx`: прозрачный SVG-слой над доской, проп `engineArrows` у `ThemedBoard` и `Board`; цвета токенами `.earrow--best|second|third|threat` в `review.css`; тесты `arrows.test.js`). Красная стрелка Диониса (наказывающий ответ) занимает место зелёной лучшей. Включается в «Настройки → Игровой процесс → Анализ → Стрелки движка» (`engineArrows`) или флажком «стрелки» в панели. Кнопка «Ссылка» внизу панели копирует `#review/<id>` (разбор доступен по ссылке любому, без входа: `GET /api/analyses/{id}` не привязан к владельцу, в ответе нет аккаунтов; тест `TestStrangerOpensTheLinkAndSeesNoAccount`); у каждого разбора в «Профиль → Партии» есть кнопка копирования ссылки. Разбор после партии (`ReviewInline`) ставит в строку браузера `#review/<id>` через `history.replaceState` (без `hashchange`, страница партии остаётся) и возвращает прежний адрес при закрытии; `ReviewPage` следует за адресом, изменённым при открытой странице. Над тремя строками линий подпись «Лучшие ходы движка», номер линии цвета её стрелки.

### Дебюты: свой репозиторий ходов и заучивание

«Дебюты» работают как Chessbook: вы собираете **свой репозиторий** (за белых или за чёрных, можно несколько) и учите его, пока не выучите до автоматизма.

- **Конструктор.** Сайт сам предлагает ходы в каждой позиции: те, что уже есть в вашем репозитории, ходы по теории дебютов (справочник ECO, по убыванию того, сколько линий теории за ними стоит, с названием дебюта) и лучший ход по движку. У каждого хода сразу видна оценка позиции после него, а у слабых ходов указана потеря шансов в процентах. Нажмите на ход: он сыграется на доске и добавится в репозиторий (при наведении на ход на доске рисуется стрелка). После добавления сайт предлагает **тренировать** репозиторий, **отменить** добавление или продолжить линию. Можно также просто ходить на доске. Справа ещё дерево всех линий и список «Нет вашего ответа» (линии, которые заканчиваются ходом соперника). Стрелки влево и вправо ходят по линии, ход можно удалить вместе со всем, что идёт после него.
- **Тренировка.** Если вы сыграли не тот ход, сайт оценивает его движком и говорит прямо: хороший ход, но мы учим другую ветку; неточность с потерей шансов в процентах; грубая ошибка, так играть не надо. Всё это считается неудачей для заучивания. Тренажёр проигрывает линию до нужной позиции, и вы играете свой ход. Новый ход сначала показывается стрелкой, его надо повторить, а потом он возвращается вопросом. Ошибка, подсказка или «Показать ход» засчитываются как неудача: ход вернётся через несколько вопросов, а на сервере упадёт на две ступени и вернётся через 10 минут. Порция новых ходов: 10 за раз.
- **Повторение до выученного.** Лестница повторений: после верного ответа ход спрашивают через 1, 3, 7, 14, 30 и 90 дней. Ход считается выученным после пяти ступеней. Для каждого репозитория видно, сколько выучено, сколько повторить сегодня и сколько новых. Сервер учитывает только первый результат каждого хода за сессию.
- Репозиторий хранится у гостя и у аккаунта Google (при входе гостя в Google репозитории переносятся).
- **Импорт и экспорт PGN (с вариантами).** На странице «Дебюты» карточка «Импорт из PGN» (файл или вставленный текст, название и цвет; цвет «как в файле» берётся из тега `Orientation`, как в изучениях Lichess), в конструкторе кнопка «Импорт PGN» добавляет файл в открытый репозиторий, а «Скачать PGN» (и «PGN» в карточке) отдаёт репозиторий файлом. Варианты в скобках становятся ветками дерева, несколько партий (главы) сливаются в одно дерево, повторяющиеся ходы не дублируются, партии с собственной начальной позицией (`FEN`) пропускаются. Комментарии и знаки `$` теряются. Файл до 4 МБ, в репозитории не больше 10 000 ходов; при ошибке в PGN сайт называет партию и полуход, и ничего не создаёт. API: `POST /api/repertoires/import`, `POST /api/repertoires/{id}/import`, `GET /api/repertoires/{id}/export`; разбор с вариантами — `pgn.ParseTrees` (`backend/internal/pgn/tree.go`), запись — `Tree.String`.

- **Статистика Lichess.** Если на сервере задан токен Lichess, у каждого хода видно, в каком проценте партий и в скольких его сыграли, и чем они кончились (цветная полоса), а список упорядочен по числу партий. Рейтинг игроков выбирается (до 1400, 1400–1800, 1800–2200, 2200 и выше). Без токена сайт честно пишет, что статистика не подключена, и работает по справочнику ECO. Как подключить: на lichess.org откройте Preferences → API access tokens, создайте токен (никакие права не нужны), добавьте в `.env` строку `LICHESS_TOKEN=...` и выполните `docker compose up -d`. Токен хранится только на сервере, ответы Lichess запоминаются на сутки, просьбу Lichess «подождите» сервер соблюдает.
- **Мои партии против репозитория.** Кнопка «Мои партии» (в карточке репозитория и в конструкторе) сравнивает ваши последние партии этим цветом (онлайн и с ботами) с репозиторием и показывает, где каждая из них вышла из него: вы забыли свой ход, соперник сыграл то, к чему вы не готовились, или линия просто кончилась. Забытый ход можно вернуть в тренировку одной кнопкой (он считается ошибкой), а то, что сыграл соперник, добавить в репозиторий: откроется конструктор на этой позиции.

- **Партии из своего PGN.** На той же странице кнопка «Проверить свои партии из PGN»: вставьте текст или выберите файл (экспорт chess.com, Lichess, ChessBase), и сайт сравнит эти партии с репозиторием так же, как сыгранные на сайте (`POST /api/repertoires/{id}/compare`, до 200 партий, 4 МБ). Партии нигде не сохраняются. Все партии считаются вашими за цвет репозитория; если в файле есть партии обоими цветами, впишите своё имя из тегов White и Black (оно запоминается в браузере), и чужие пропустятся. Партии со своей начальной позицией и короче двух ходов пропускаются.

Пока нет: режима «угадай ход» по партиям мастеров и учёта транспозиций (дерево хранит путь ходов, а не позицию).

### Настройки «Игровой процесс»

«Настройки → Игровой процесс» (`#settings/play`), по образцу chess.com, с группами «Общие», «Онлайн», «Заочные партии», «Вызовы», «Анализ» и «Задачи». Работают сейчас:
- **Общие:** всегда превращать в ферзя (Alt при ходе возвращает выбор фигуры), подтверждать сдачу и ничью (в игре с ботом, онлайн и против движка), показывать допустимые ходы, режим «Доска в центре» (тот же, что значок в углу), белые всегда внизу доски (игры, задачи, штурм, дуэль), способ рокировки (королём на две клетки, королём на свою ладью или оба способа).
- **Онлайн:** премувы (ходы заранее, пока ходит соперник: можно поставить до 30 подряд, каждый следующий выбирается на доске после предыдущих; красные поля, ходы играются по очереди, как только становятся возможными; если очередной невозможен, очередь сбрасывается; отмена всех: Esc или правая кнопка), предупреждение о времени (часы краснеют при 20 секундах, сигнал на 10, 3, 2, 1 секунде), подтверждение хода (показывается ход и кнопки «Подтвердить ход» и «Отмена»), запрет второй одновременной партии.
- **Вызовы:** рейтинг открытого вызова, то есть насколько слабее и сильнее может быть соперник при подборе (пустое поле: без ограничений; границы соперника тоже действуют).
- **Анализ:** оценка движка в разборе (шкала, график, число), автоматический разбор после партии, значки классификации ходов в списке.
- **Задачи:** режим очков (`puzzlePoints`, выключен по умолчанию: рейтинговые задачи приносят очки, а не меняют рейтинг; считает сервер, подробности в WEB-PLAN «Очки за задачи»), уровень сложности (случайно, легче, по вашему уровню, сложнее: сдвиг рейтинга подбора на ±150 или случайно в пределах 300), скрыть рейтинг, показывать темы сразу, таймер задачи.
Пункты, для которых на сайте ещё нет самой функции, показаны бледными с пометкой «скоро»: заочные партии, режим отпуска, друзья и входящие вызовы, время на ход, комментарии Тренера. У каждой страницы настроек своя кнопка «Вернуть стандартные».

### Подбор соперника, рейтинг Glicko-2 и дуэль

«Играть → Играть онлайн»: в блоке «Быстрая игра» выбираете вид (рейтинговая или обычная) и время (1 мин, 2+1, 3 мин, 3+2, 5 мин, 10 мин и т. д.), и сайт ищет живого соперника. Очередь подбирает людей с близким рейтингом: сначала разница до 100 пунктов, за каждую секунду ожидания окно растёт на 25 (до 1000), так что никто не ждёт вечно, а новичку не достаётся мастер сразу. Найдя пару, сайт открывает партию (цвета разыгрываются). Ожидание можно отменить; если покинуть страницу, поиск отменится сам. Партия с другом по ссылке по-прежнему есть, у неё тоже можно включить «рейтинговая».

**Рейтинг** считается по Glicko-2 (то же семейство систем, что у chess.com и Lichess): три числа, рейтинг, неопределённость (RD) и волатильность. Новичок начинает с 1200, RD 350, поэтому первые партии двигают рейтинг сильно (до ±160 за партию), потом всё слабее; пока RD больше 110, рядом с рейтингом стоит «?». Рейтингов несколько, как на chess.com: «Пуля» (партия короче 3 минут по формуле «время + 40 ходов добавки»), «Блиц» (до 8 минут), «Рапид» (остальное) и «Дуэль». Считаются только партии двух людей с часами; боты и обычные партии рейтинг не меняют; партия короче 4 полуходов тоже (сдача на первом ходу не наказывается). Итог партии показывает «Блиц: 1200 → 1362? (+162)», рейтинги всех категорий видны на «Профиль → Обзор».

**Тактическая дуэль** (`#puzzles/duel`): два человека, подобранные по дуэльному рейтингу, решают одни и те же задачи (от лёгких к сложным, начало зависит от рейтингов) 3 минуты; перед началом 5 секунд на подготовку. Решённая задача — очко, ошибка пропускает задачу и считается при равенстве очков. Очки соперника видно в ходе дуэли. Побеждает тот, у кого больше очков; результат меняет дуэльный рейтинг.

### Задачи

**Тактический штурм** (`#puzzles/rush`): задачи идут подряд от лёгких к сложным (первая около 500, каждая решённая добавляет 50), серия на 3 или 5 минут заканчивается первой ошибкой или когда выйдет время. Следующая задача подгружается, пока решается текущая. Рейтинг задач не меняется; сервер хранит каждую серию (таблица `rush_results`, миграция 0009) и показывает рекорд по длине серии. Слабых мест: счёт приходит из браузера, то есть рекорд честный только по слову игрока.

«Задачи» делятся на пять разделов: «Рейтинговые» (подбор по рейтингу, `#puzzles`), «По темам» (выбор темы из
списка, `#puzzles/themes`), «Задача дня» (`#puzzles/daily`), «Тактический штурм» (`#puzzles/rush`) и «Тактическая дуэль»
(`#puzzles/duel`, с живым соперником). Переключать их можно в левом меню (группы «Играть» и «Задачи» выпадают в окошке справа
от пункта при наведении, как на chess.com, и не раздувают меню) и вкладками над панелью справа; при перезагрузке страница
остаётся в своём разделе. **Рейтинг меняется только в рейтинговых задачах**, остальные два раздела — тренировка. Тактические задачи берутся из открытой базы Lichess (CC0). Задача подбирается по вашему рейтингу в задачах
(новичок начинает с 1000; рейтинг считается по Эло, у задач рейтинг Lichess неизменный). Соперник делает ход,
вы ищете лучшие ходы; любой ход, дающий мат, тоже засчитывается. Есть подсказка (подсвечивается фигура),
показ решения, тема на вкладке «По темам» (вилка, связка, мат в 2 хода и т. д.). Рейтинг меняется только за первую попытку
по каждой задаче: неверный ход или показ решения засчитывается как неудача, дальше можно доиграть для
тренировки. Рейтинг хранится у гостя и у аккаунта Google (при входе гостя в Google рейтинги объединяются).
Превращение пешки выбирается в окне на доске (см. ниже, «Превращение пешки»), поэтому задачи на недоферзя решаются.

**Превращение пешки.** Когда пешка доходит до последней горизонтали, на клетке хода открывается столбик из ферзя,
коня, ладьи и слона (как на chess.com), фигуры берутся из выбранного набора и цвета пешки. Работает и при
перетаскивании, и при клике; Esc или клик по другой клетке отменяют выбор (пешка остаётся на месте). Окно рисует
общая доска `components/Board.jsx`, поэтому оно одинаково в игре против движка, с ботами, онлайн, в задачах, в
репозитории ходов и в своей ветке разбора. Логика без зависимостей в `components/promotion.js` (тесты в `npm test`).

«Задача дня» (`#puzzles/daily`): одна задача на всех, меняется в полночь по Гринвичу. Выбирается без таблицы задач:
из задач рейтинга 1400–1800 с популярностью не ниже 90 берётся та, на которую указывает хеш даты
(`GET /api/puzzles/daily`; ответ как у `next` плюс `daily: {date, status}`, где статус `new`, `solved` или
`failed` по первой попытке дня у вошедшего). Это тренировка: рейтинг не меняется. Результат первой попытки дня
пишет `POST /api/puzzles/daily/result` в таблицу `daily_puzzle_results` (миграция 0008; при слиянии гостя с
аккаунтом результаты переносятся, на совпавший день остаётся результат основного аккаунта). Задачи «По темам»
вообще ничего не пишут.

База не лежит в репозитории: скачайте `lichess_db_puzzle.csv.zst` (около 250 МБ) с
<https://database.lichess.org/#puzzles> в `data/puzzles/` (папка не попадает в git) и загрузите подборку в MySQL
(в Docker база слушает порт 3317 на этом компьютере; пароль `MYSQL_PASSWORD` из `.env`):

```powershell
go run ./backend/cmd/puzzleimport -file data/puzzles/lichess_db_puzzle.csv.zst -dsn "dyanis:ПАРОЛЬ@tcp(127.0.0.1:3317)/dyanis"
```

Команда оставляет самые популярные задачи каждой сотни рейтинга (всего около 100 000, `-total`), отбрасывает
неустоявшиеся и неигранные и проверяет, что решение — допустимая цепочка ходов. `-dry-run` только показывает,
что будет загружено. Повторный запуск добавляет лишь новые задачи.

### Игра с другом (онлайн)

«Онлайн» → выберите время и цвет → «Создать партию» → отправьте ссылку другу. Он открывает её и нажимает
«Играть как гость» (или входит через Google), партия идёт по часам сервера. Ссылку могут открыть и зрители.
Есть сдача, предложение ничьей, отмена в начале партии, реванш; после конца партии карточка итогов с кнопкой
«Смотреть отчёт», а сыгранные партии лежат в профиле. Партии хранятся в MySQL и переживают перезапуск сервера.
Нужна база (в Docker она есть). Ходы и часы ведёт сервер, клиент только показывает. Подробности в `WEB-PLAN.md`,
раздел «Онлайн-игра».

### Другие шахматы (десять видов)

Группа «Другие шахматы» в меню: Атомные, Царь горы, Орда, Chess960, Слепые, Утиные, Dice chess, Туман войны,
Crazyhouse и Шведские (Bughouse, четверо по ссылке). Играют люди, по ссылке или быстрым подбором, без рейтинга
и без разбора движком, кроме Chess960 (после партии кнопка «Разбор партии»: движок оценивает позиции без прав рокировки, дебютной книги нет; `backend/internal/analysis/variant.go`, `POST /api/analyses/variant`). Dice chess: в начале очереди бросаются три кубика сразу, фигурами можно ходить в любом порядке. Правила лежат в `backend/internal/variants` (своя доска,
каждый вид регистрируется в `init`, тесты сверяют базу с движком на случайных партиях и перфтом), партии
обслуживает `backend/internal/vplay` (таблица `variant_games`, миграции 0018 и 0019), сайт в `web/src/variants/<id>/`.
Чтобы добавить вид: файл правил в `variants`, папка с `index.jsx` в `web/src/variants/`, больше ничего (меню и каталог
строятся из реестра). Контракт, правила каждого вида и решения: [`VARIANTS-PLAN.md`](./VARIANTS-PLAN.md). Тесты:
`go test -race ./backend/internal/variants/ ./backend/internal/vplay/`.

### Запуск без Docker (для разработки)

Два процесса: Go-сервер с движком и интерфейс на React (без `-dsn` результаты хранятся в памяти).

```bash
# 1. сервер разбора (порт 127.0.0.1:8080)
go run ./backend/cmd/server -evalfile engine/net-kingf-m4.bin

# 2. интерфейс (в другом терминале), http://localhost:5173
cd web; npm install; npm run dev
```

Вкладка «Разбор партии»: вставьте PGN (или загрузите файл, или нажмите «Пример»),
выберите глубину, нажмите «Разобрать». Страница показывает доску, график оценки (клик и
перетаскивание по нему переходят к ходу), список ходов со значками классов, оценку и лучшую
линию движка, стрелку лучшего хода, название дебюта, точность игроков и ключевые моменты.
Стрелки ←, →, Home, End листают партию. Без Node: `cd web; npm run build`, затем
`go run ./backend/cmd/server -evalfile engine/net-kingf-m4.bin -static web/dist` и открыть
http://127.0.0.1:8080.

### Настройки: доска, фигуры, фон, звук

Пункт меню «Настройки → Доска и фигуры»: вкладки «Доски», «Фигуры», «Фон», «Готовые настройки» с
предпросмотром на живой доске, кнопки «Сохранить» и «Отмена», координаты (внутри, снаружи или
выключены), подсветка последнего хода, способ хода (перетаскивать, нажимать или оба), скорость
анимации, звуки. Настройки действуют на доске разбора и в игре с ботом и хранятся в браузере (`localStorage`);
после входа в аккаунт они же сохраняются на сервере и идут за пользователем на другое устройство.

**Свои наборы фигур, доски, фоны и звуки** кладите в `web/src/themes/` (`pieces/`, `boards/`,
`backgrounds/`, `sounds/`) и пересобирайте сайт (`docker compose up -d --build web`): код править не
нужно. Формат файлов и лицензии — в [`web/src/themes/README.md`](./web/src/themes/README.md).
Тесты логики настроек: `cd web; npm test`.

Каждый ход получает значок: блестящий (!!, жертва, которая оправдана), сильный (!, единственный
хороший ход), лучший, отличный, хороший, теория, упущенная возможность (не использована ошибка соперника), неточность (?!),
ошибка (?), зевок (??). Значок
виден на доске, в списке ходов и в карточке справа сверху. После партии с ботом или онлайн «Смотреть
отчёт» открывает разбор на месте, без перехода на другую страницу.

API: `POST /api/analyses` с телом `{"pgn": "...", "game": 1, "depth": 14}` возвращает `{"id"}`;
`GET /api/analyses/{id}` — статус (`queued`, `running`, `done`, `error`), прогресс и готовый
отчёт; `GET /api/analyses` — разборы вошедшего пользователя, `DELETE /api/analyses/{id}` — удалить
свой; `GET /api/me`, `POST /api/auth/guest`, `POST /api/auth/logout`, `PUT /api/me/settings` — аккаунт. Разборы идут по одному (каждый уже занимает все ядра), очередь на 20, результаты
хранятся в памяти, а при заданном `-dsn` (или `DYANIS_DB_DSN`) готовые ещё и в MySQL.

## Структура проекта

Репозиторий поделён на три независимые части, чтобы менять одну, не трогая остальные:

```
engine/     шахматный движок и всё, что его касается (отдельно от сайта)
backend/    сервер сайта: разбор партий, API, база данных
web/        React-интерфейс
deploy/     Dockerfile'ы и конфиг nginx; в корне — docker-compose.yml, .env
```

**Движок отделён от сервера на уровне компилятора.** Всё внутреннее устройство движка
лежит в `engine/internal/`, и Go не даёт импортировать его снаружи `engine/`. Серверу
доступен только «фасад» — пакет [`engine`](./engine/engine.go): правила шахмат (позиция,
FEN, ходы, SAN, окончание партии) и поиск («оцени позицию, найди лучший ход»). Если
захочется заменить движок, достаточно сохранить этот интерфейс — в `backend/` менять
ничего не придётся. Контракт и порядок замены описаны в [`engine/README.md`](./engine/README.md).

```

  cmd/
    cli/             запуск движка: игра в терминале, perft, UCI
    wasm/            сборка движка в WebAssembly (бот в браузере)
    match/           матч двух UCI-бинарников: Elo ± интервал, SPRT
```

## Для разработчиков

Сила игры измеряется **только матчами** между версиями, не числом узлов.
Обычный порядок работы с изменением поиска:

```bash
cd engine
go build -o baseline.exe ./cmd/cli       # версия до правки
# ... правка ...
go build -o candidate.exe ./cmd/cli
go build -o match.exe ./cmd/match
./match.exe -a candidate.exe -b baseline.exe -movetime=100 -pairs=300 \
  -concurrency=16 -elo0=0 -elo1=10 -openbook=assets/gm2001.bin
```

Сравнение двух сетей — тем же `match.exe` с одним бинарником и разными
опциями: `-aopts "EvalFile=net-a.bin" -bopts "EvalFile=net-b.bin"`.

```bash
# CPU-профиль поиска (тоже из engine/)
go run ./cmd/profile -threads=1 -budget=5s
go tool pprof -top cpu.prof

# Texel-тюнинг ручной оценки
go run ./cmd/tune -mode=findk
go run ./cmd/tune -mode=tune -k=1.504328 -threads=8
```

> **PowerShell 5.1:** значения вида `-carry=file.json` берите в кавычки
> (`"-carry=file.json"`), иначе следующие флаги молча теряются.

Данные для обучения сети (`engine/data/`) в репозиторий не входят: их порождает
`engine/cmd/gendata`, процесс описан в [`engine/NNUE.md`](./engine/NNUE.md).

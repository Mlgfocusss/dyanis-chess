# Переключатель языка RU/EN: заметки (I18N-NOTES.md)

Сделано 2026-10-22. Для переноса в WEB-PLAN.md главным агентом. Язык-источник русский; английский добавлен ко всему интерфейсу, кроме списка в конце («Что осталось по-русски»).

**Строку плана про «многоязычность» в списке «не делаем» нужно заменить:** многоязычность делаем, сделаны русский и английский (`web/src/i18n/`), добавить третий язык значит добавить `i18n/<код>/` и код в `LANGUAGES`.

## Как устроено (без новых зависимостей)

- `web/src/i18n/index.js`: словари, `translate`, `tr`, `useT`, `useLang`, `tOr`, `tOpts`, `tx`, `serverMsg`, `locale`, `formatDate/Time/DateTime/Number`, `getLanguage/setLanguage`.
- `web/src/i18n/detect.js`: `LANGUAGES`, `detectLanguage(navigator)` (ru* → ru, иначе en), без импортов, его берёт `settings/model.js`.
- `web/src/i18n/I18nProvider.jsx`: `SettingsI18n` стоит в `Root.jsx` внутри `SettingsProvider`: ставит язык для `useT`, для `tr` и `<html lang>`.
- Словари: `web/src/i18n/ru/<область>.js` и `en/<область>.js` (файл = первый сегмент ключа), плоские ключи `menu.home`, значение строка или объект форм множественного числа. `i18n/ru.js` и `en.js` собирают области через `merge` (повтор ключа в двух областях бросает ошибку). Нового языка нет, но структура готова.
- Настройка `language` ("ru" | "en") в `settings/model.js` (в `INTERFACE_KEYS`, `sanitize` проверяет), по умолчанию по `navigator.language`; хранится в localStorage и на сервере вместе с остальными настройками (`User.settings`), миграция не понадобилась. Скрипт в `web/index.html` ставит `<html lang>` до загрузки React (его проверяет `settings/theme.test.js`).
- Переключатели: «Настройки → Интерфейс → Язык» (применяется и сохраняется сразу, не черновиком; `SettingsPage` подтягивает черновик, чтобы кнопка «Сохранить» не загоралась) и маленькая кнопка «RU | EN» (`i18n/LangSwitch.jsx`) над карточкой профиля в меню слева. На телефоне нижняя панель переполнена (одиннадцать пунктов), поэтому там кнопка стоит вверху главной страницы (`langsw--mobile`), а в самой панели скрыта.

## API (не менять)

- В компоненте: `const t = useT(); t("area.key", { name })`. Хук нужен в каждом компоненте, который показывает текст (иначе он не перерисуется при смене языка: контекст меняется, а не вся страница пересоздаётся, состояние партий, часов и форм сохраняется).
- Вне компонентов (чистые функции, которые зовут при отрисовке) и в обработчиках, которые живут дольше одной отрисовки: `tr("area.key", params)`: читает язык в момент вызова. Константы уровня модуля с текстом не делать: хранить ключ (`label: "menu.home"`), переводить при показе: `t(label)`, а для списков `<Segmented options>` есть `tOpts(t, [[value, key], ...])`.
- Множественное число: значение-объект `{ one, few, many, other }`, вызов `t("k", { n })` (форма по `n` или `count`, `Intl.PluralRules`). Подстановка `{name}`. Нет ключа в en: показывается русский текст (в dev-сборке один раз предупреждение в консоли, в тестах нет). Нет и в ru: показывается ключ.
- Даты и числа: `locale()` в `toLocale*String(locale(), ...)`, либо `formatDate/Time/DateTime/Number`. Десятичная запятая в `num()` и `formatGames` зависит от языка.
- **Данные с русскими текстами внутри**: `tx(русскийТекст)` находит текст среди русских значений словаря и отдаёт перевод (так переведены описания и причины окончания видов шахмат, имена игроков-ботов в PGN, названия классов в «Тренере»). Текст должен лежать в словаре как значение; тест `i18n.test.js` проверяет это для всех видов шахмат.
- **Тексты ошибок сервера** (Go, русские): `serverMsg(body.error)` в обёртках API; в английском переводятся известные сообщения (словарь `srv.*`, 169 штук, без чисел и без технических вроде «ожидался JSON»), остальные остаются как пришли.
- Боты: имена, описания, реплики и категории с сервера переводятся по id бота: `bots/botText.js`, ключи `bots.<id>.<поле>` и `bots.cat.<категория>` (бэкенд не менялся). Категории форума: `forum.cat.<id>.name|desc`. Страны: поля `ru`/`en` из `/api/countries`, `countries/countryList.js` сортирует и ищет по языку. Названия дебютов: `openings/names.js` берёт `name` (английское) или `nameRu` по языку. Рейтинговые категории: `online/rating.js: categoryName`. Темы досок, фигур, фонов и звуков: `themes/names.js: themeName` + словарь `themes.*`. Темы задач: `puzzleTheme.<id>`.

## Как добавить строку

1. Ключ `область.имя`; русский текст в `i18n/ru/область.js`, английский в `i18n/en/область.js`. Новую область дописать в `i18n/ru.js` и `i18n/en.js`.
2. В коде `t("область.имя")`. Общие слова уже есть: `common.cancel`, `common.save`, `common.soon`, `common.days` и т. д.
3. `cd web && npm test`: тест `i18n/i18n.test.js` ловит ключ без английского, расхождение `{подстановок}`, сломанные формы множественного числа.

Две ловушки, на которых уже ошибались: (1) локальная переменная по имени `t` внутри компонента (`const t = text.trim()`, `.map((t) => ...)`) затеняет функцию перевода, вызов `t("...")` внутри такой области ломается: называйте такие переменные иначе; (2) `React.StrictMode` перерисовывает дважды, это безопасно, язык ставится идемпотентно.

## Проверено

- `cd web && npm test` (332 теста, из них 10 новых в `i18n/i18n.test.js`: одинаковые наборы ключей и подстановок, плюрализация ru/en, подстановка, откат en → ru, `tr`/`tx`/`serverMsg`, определение языка, санитайзер настройки, покрытие определений видов шахмат), `npx vite build`.
- Глазами в Edge (puppeteer-core, сервер на 127.0.0.1:8092 против базы Docker): язык по умолчанию из `navigator.language` (en-US → английский, `<html lang>` en); обход страниц на английском: главная, меню, вход, все пять разделов настроек, профиль (обзор и статистика), онлайн-лобби, боты, игра с движком, дебюты, разбор, доска анализа, таблица лидеров, сообщество (все пять вкладок), форум, виды шахмат (каталог, лобби, комната, Atomic), задачи (рейтинговые, по темам, штурм, дуэль), тренер, уроки; партия с ботом до конца (ход, сдача, итоги, «Смотреть отчёт», разбор на английском); переключатель «RU | EN» в меню без перезагрузки (состояние страницы сохраняется, проверено маркером в `window`), сохранение после перезагрузки (localStorage), переключение на странице настроек (кнопка «Сохранить» не загорается), 1440x900 и 390x844, тёмная и светлая тема, горизонтальной прокрутки на 390 px нет, ошибок в консоли нет. Скриншоты лежат в scratchpad (`i18nshots`).

## Решения

- Своя i18n, а не библиотека: нужны были только ключи, подстановка и плюрализация; десять строк контекста вместо зависимости.
- Язык применяется сразу и сохраняется сразу (не по кнопке «Сохранить»), потому что быстрый переключатель в меню работает так же; в `INTERFACE_KEYS` ключ есть, поэтому «Вернуть стандартные настройки интерфейса» сбрасывает его к языку браузера (после «Сохранить»).
- Данные сервера на русском (имена ботов, категории форума, ошибки) переводятся на фронте словарём, бэкенд не менялся.
- Вставленные на странице разбора PGN-примеры и PGN-теги («Онлайн-партия» как Event) остаются данными; в заголовке разбора Event и имена-боты показываются через `tx`.
- Названия настроек и пунктов меню в английском взяты по смыслу и по образцу chess.com/Lichess (Puzzle Rush, Puzzle Duel, Analysis board и т. д.).

# Блокировка игроков и жалобы (2026-10-22): заметки для документации

Статус: сделано и проверено тестами и в Edge. Для запуска нужна миграция `0026_blocks_reports.sql` (применяется сама при старте сервера) и пересборка Docker. Модераторов по-прежнему назначает `FORUM_ADMINS`.

## Блокировка

- Таблица `blocks (blocker_id, blocked_id, created_at)`, каскад от `users`. Код: `store/blocks.go`, `community/blocks.go`.
- API (`/api/community/`): `GET blocks` (список и `max`), `PUT blocks/{id}` (заблокировать, повтор даёт тот же ответ), `DELETE blocks/{id}`. Не больше 500 блокировок (409), 30 действий в минуту (429), себя нельзя (400).
- `store.Block` одной транзакцией: ставит блокировку, удаляет дружбу (обе строки), запросы в друзья в обе стороны, отменяет открытые вызовы между двоими, помечает прочитанным то, что заблокированный успел написать.
- Закрыто на сервере в обе стороны (проверка `Service.gate`): сообщение, запрос в друзья, вызов (в том числе заочный), принятие вызова и запроса. Заблокированному отвечают нейтрально («не удалось отправить», «не удалось отправить запрос», «не удалось отправить вызов»), заблокировавший видит «Вы заблокировали этого игрока: сначала разблокируйте». Снятие блокировки дружбу не возвращает.
- `GET friends/{id}` для заблокировавшего даёт `relation: "blocked"`; заблокированный видит обычное «не друзья».
- Поиск игроков: заблокированный не находит заблокировавшего (в запросе `SearchUsers`); заблокировавший находит всех.
- Присутствие «на сайте»: `Service.people` не показывает заблокировавшего как «в сети» тому, кого он заблокировал (списки переписок и вызовов).
- Подбор соперника (`match`): `Config.Avoid` (в `main.go` это `db.BlockedWith`) читается один раз, когда человек встаёт в очередь; заблокировавшие друг друга не попадают в пару ни в игре с часами, ни в дуэли. Блокировка, сделанная уже после вставания в очередь, действует со следующего поиска. Если чтение блокировок не удалось, человек играет без этой проверки.
- `MergeUsers` переносит блокировки гостя (в обе стороны, без блокировки аккаунта на самого себя) и удаляет дружбу и запросы, которые после переноса оказались рядом с блокировкой.
- Форум: сервер отдаёт сообщения как раньше, в `PostJSON` флаг `blockedByMe`; страница прячет текст за кнопкой «Показать».
- Партии, которые уже идут между двумя игроками (в том числе заочные), блокировка не трогает: `play` не менялся. Ссылки-приглашения публичны и тоже не тронуты.

## Жалобы

- Таблица `reports` (миграция 0026): вид цели (`message`, `forum_post`, `forum_topic`, `user`), причина (`spam`, `abuse`, `cheating`, `other`), комментарий до 300 символов, `snapshot` (копия текста на момент жалобы; для темы заголовок и первое сообщение, для игрока имя), имена автора жалобы и цели, `topic_id`, статус, действие, кто и когда закрыл. Автор жалобы и цель при удалении аккаунта получают NULL, жалоба с копией остаётся. `open_key` (1, пока жалоба открыта) с уникальным ключом даёт «одна открытая жалоба на пару автор + цель».
- API (код в `forum/reports.go`, маршруты смонтированы в `main.go`): `POST /api/reports` (любой вошедший, гость тоже; нельзя на себя; 10 в час; личное сообщение может обжаловать только его получатель; удалённое сообщение форума нельзя); `GET /api/reports?status=open|closed` и `POST /api/reports/{id}/close` с `{"action": "none"|"delete"|"lock"}` только для модераторов (403 остальным). `delete` удаляет сообщение или тему форума, `lock` закрывает тему; закрытие закрывает все открытые жалобы на ту же цель.
- Модераторам `GET /api/forum/categories` отдаёт `moderator: true` и `openReports`; остальным этих полей нет. Страница очереди `#forum/reports`, ссылка «Жалобы (N)» на главной форума видна только модераторам.
- Кнопки «Пожаловаться»: личное сообщение (под чужим сообщением в переписке), сообщение и тема форума, страница игрока (`RelationBar`). «Заблокировать»: страница игрока и шапка переписки. Вкладка «Сообщество → Заблокированные».

## Решения и ограничения

- Жалобы живут в пакете `forum` (там уже есть модераторы), новый пакет не заводил.
- Переписка с заблокированным не читается (как и с удалённым другом, см. «Сообщения»): чтобы пожаловаться на личное сообщение, делать это до блокировки.
- В запросе `/api/reports` идентификатор цели передаётся строкой.
- Тестовые прогоны на настоящей базе оставляют жалобы: тесты убирают их через `store.DeleteReport`.
- Не сделано: просмотр модератором контекста переписки (только само сообщение), автоматическое действие по числу жалоб, уведомление автору жалобы о решении.
- Строки новых экранов: `web/src/i18n/{ru,en}/safety.js` (область `safety`).

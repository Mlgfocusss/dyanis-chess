# VARIANTS-PLAN: другие виды шахмат на сайте (2026-10-21)

Отдельная группа «Другие шахматы» в боковом меню. Здесь план, разделение работы между агентами, контракт между частями и журнал каждого агента. Читать целиком перед началом работы. Общие правила проекта (русский интерфейс, тёмный дизайн и светлая тема только через токены, без эмодзи, значки SVG в `web/src/ui/Icon.jsx`, не коммитить, не трогать внешние сервисы, подводные камни) описаны в `WEB-PLAN.md`, раздел «Текущее состояние» и «Правила работы с автором».

## 1. Решения автора

- Видов: Туман войны (Fog of War), Dice chess, Утиные (Duck), Слепые (Blindfold), Атомные, Crazyhouse, Шведские (Bughouse), Царь горы (King of the Hill), Орда (Horde), Chess960.
- Играют **люди** (по ссылке-приглашению и быстрым подбором), **без рейтинга**, **без разбора партии движком**: наш движок знает только классические правила. Ботов нет.
- **Dice chess (ответ автора):** перед каждым из трёх ходов очереди бросается кубик (шесть граней, шансы равны), он задаёт тип фигуры (1 пешка, 2 конь, 3 слон, 4 ладья, 5 ферзь, 6 король); ходов за очередь **3**, одной и той же фигурой можно ходить несколько раз; игра до мата. Допущения, которые агент фиксирует в журнале: если ходов выпавшей фигурой нет, этот из трёх ходов пропускается; шаха нет (король ходит и может встать под бой), партия кончается взятием короля (это и есть «мат» в этой игре); кубик перед следующим ходом бросается только после предыдущего хода, и его видят оба.
- Правила брать так: Atomic, King of the Hill, Horde, Crazyhouse, Chess960 — как на Lichess; Fog of War — как на Chess.com (короля берут, шаха нет, видны свои фигуры и поля, на которые можно сходить); Duck — оригинальные правила (ход фигурой, затем обязательная постановка утки на любое свободное поле, не на поле, где она уже стояла; утку нельзя взять, она блокирует, шаха нет, побеждает взявший короля, у кого нет ходов — выигрывает); Bughouse — как на Chess.com (2 на 2, две доски, взятая фигура уходит в резерв напарника, часы у каждого свои). Любое отклонение записывать в журнал агента.

## 2. Архитектура

Принцип: правила видов живут в **новом пакете** и не трогают ни `engine/`, ни `backend/internal/play`. Онлайн-партии видов обслуживает **новый пакет** `backend/internal/vplay` (по образцу `play`: WebSocket со снимками, часы на сервере, чат, ничья, сдача, реванш, переподключение, сохранение в MySQL). Существующие тесты `play`, `analysis`, `engine` обязаны проходить.

```
backend/internal/variants/   правила: база классических шахмат + виды, всё чистые функции и тесты
backend/internal/vplay/      партии: хаб, комнаты, часы, WebSocket, подбор, сохранение
web/src/variants/            страницы и интерфейс; по папке на вид: web/src/variants/<id>/index.js(x)
```

Фасад движка (`engine/engine.go`) используется **только в тестах** `variants` как эталон: базовые классические шахматы сверяются с `engine.Position.LegalMoves` на случайных партиях. Своя доска (8x8, FEN-подобная запись), а не `engine.Position`, потому что видам нужны утка, резерв, взрывы, 36 пешек и т.п.

### Контракт (первый агент уточняет и записывает окончательный вариант в раздел 5, остальные ему следуют)

Действие — строка. Ход фигурой `e2e4` (с превращением `e7e8q`), высадка `P@e4`, утка `@e5`, конец очереди `-`. Вид описывается так (имена примерные, окончательные в разделе 5):

```go
type Variant interface {
    ID() string; Name() string          // "atomic", "Атомные шахматы"
    New(o Options) State                // o.Seed для случайных видов (960, кубик)
}
type State interface {
    Turn() Side                         // чей ход; часы переключаются, когда Turn() меняется
    Legal() []string                    // все допустимые действия ходящего на текущем шаге
    Apply(action string) (notation string, err error)   // Duck: ход, затем утка (Turn не меняется между шагами); Dice: три хода и броски
    Over() (result, reason string, over bool)           // "1-0"/"0-1"/"1/2-1/2"
    View(side Side) any                 // JSON для клиента этого игрока (туман скрывает чужое); зрителю side == ""
    Marshal() ([]byte, error)           // полное состояние для базы; variants.Load(id, data)
}
```

Снимок партии для клиента — это `View` плюс общие поля `vplay` (игроки, часы, ходы с записью, предложения, чат, присутствие). В `View` общее для всех видов: `board` (клетка → фигура, как `{"e4": "wP"}`, утка `"xD"`), `legal` (только для ходящего), `last` (клетки последнего действия), `check` (клетки королей под боем, если шах есть), `extra` (свободный JSON вида: резерв, выпавшие кубики, скрытые клетки, ...).

Реестр: каждый вид регистрируется в `init()` своего файла (`variants.Register(...)`), без правки общих списков. На сайте то же: каждый вид — папка `web/src/variants/<id>/` с `index.js`, которую подхватывает `import.meta.glob` (название, значок, краткие правила, необязательные слоты интерфейса: `Panel` над и под доской, `boardProps(view)`, `onSquare`/`onDrop`-обработчики, `Controls`). Общий файл (`Root.jsx` меню, `variants.css`) агенты видов **не правят**, кроме добавления недостающей точки расширения (минимально, перечитав файл прямо перед правкой, потому что рядом работают другие агенты).

#### 5.F.1. Go: пакет `variants`

Файлы: `types.go` (Side, Kind, Piece, Sq, Move, MoveRec), `position.go` (Position, FEN, Attacked), `movegen.go` (ходы, рокировка, `Apply`, `Perft`), `notation.go` (SAN), `rules.go` (интерфейс `Rules`, `ClassicRules`, `Options`, `ClassicResult`), `game.go` (`Game`, `State`, `View`), `registry.go` (`Register`, `Get`, `All`, `Prepare`, `Replay`), `classic.go` (вид `classic`, скрытый). Тесты: `classic_test.go` (перфт, сверка с движком), `extension_test.go` (мини-виды на каждую точку расширения: **образцы для копирования**).

**Типы.** `Side` (`NoSide`, `White`, `Black`; в JSON `""`, `"white"`, `"black"`), `Kind` (`Pawn…King`, `Duck`), `Piece{Kind, Side, Promoted}` (код для сайта `p.Code()`: `"wP"`, `"bN"`, утка `"xD"`), `Sq` (0..63, a1=0, `NoSq=-1`; `ParseSq("e4")`, `MakeSq(file, rank)`), `Move{From, To, Promo, Drop, Castle, Rook, EnPassant, SetsEP}` (`Rook` читать только при `Castle`; у высадки `From=NoSq`, `Rook=NoSq`).

**Position** (`position.go`): `B [64]Piece`, `Turn`, `Castle [3][2]Sq` (клетка ладьи права: `Castle[side][0]` короткая, `[1]` длинная, `NoSq` нет права; король стоит где стоит), `EP`, `Half`, `Full`, `Pocket [3][8]int8` (резерв `[сторона][вид]`). `ParseFEN` (KQkq, X-FEN и Shredder-FEN `HAha`), `p.FEN()`, `p.Placement()`, `p.Board()` (карта для сайта), `p.Apply(rules, mv) *Position` (копия), `p.LegalMoves(rules)`, `p.PseudoMoves(rules)`, `p.Attacked(sq, by)`, `p.InCheck(side)`, `p.KingSq(side)`, `p.FixCastling()`, `Perft(rules, p, depth)`.

**Действия** (строки): ход `e2e4`, превращение `e7e8q`, рокировка `e1g1` (король на две клетки; при `CastleAsKingTakesRook()` пишется `e1h1`: король берёт свою ладью), высадка `P@e4`. Вид добавляет свои (утка `@e5`, конец очереди `-` и т.д.) и описывает их в своём разделе. `Encode(rules, mv)` и `Find(rules, moves, action)` переводят туда и обратно.

**State** (то, чем играет сервер):

```go
type State interface {
    Turn() Side                                         // кто действует; часы переключаются, когда значение меняется
    Legal() []string                                    // все допустимые действия на этом шаге
    Apply(action string) (notation string, err error)   // одно действие
    Over() (result, reason string, over bool)           // "1-0"/"0-1"/"1/2-1/2" и ключ причины
    View(viewer Side) View                              // viewer: White, Black или NoSide (зритель)
}
// необязательные, сервер проверяет приведением типа:
type Timeouter interface{ Timeout(loser Side) string }                         // итог при падении флажка (по умолчанию проигрывает упавший)
type MoveRedactor interface{ RedactMoves(viewer Side, moves []MoveRec) []MoveRec } // скрыть чужие ходы в списке (туман)
type Finisher interface{ Finish(result, reason string) }                          // сервер сообщает об окончании не от правил (сдача, флажок, ничья): открыть всё, не выдавать ходы
```

**View** (общая часть снимка для всех видов): `{"board": {"e4":"wP",...}, "turn":"white", "legal":[...] (только если viewer == turn и партия идёт), "last":["e2","e4"], "check":["e8"], "extra": <свободный JSON вида>}`. `Over()`-причины: константы `ReasonCheckmate`, `ReasonStalemate`, `ReasonInsufficient`, `ReasonFiftyMoves`, `ReasonRepetition`, `ReasonKingCaptured`, `ReasonNoMoves`; вид может вернуть свою строку (`"king-of-the-hill"`), текст для неё задаётся в `reasons` его `index.js` на сайте.

**Определённость.** `State` обязан быть детерминированным: одни `Options` и одни действия дают одно состояние. Так партия поднимается из базы (`variants.Replay(id, options, actions)`). Случайность (расстановка 960, кубик) берётся только из `Options.Rand()` (генератор от `Options.Seed`; сид сервер задаёт при создании партии и хранит; не показывать клиенту, если из него выводятся будущие броски). Для кубика: вызывать `Rand()` один раз при создании состояния и хранить генератор в нём, бросать в порядке действий.

**Как добавить вид в Go за 5 шагов**

1. Файл `backend/internal/variants/<id>.go` в пакете `variants` (общих списков править не нужно).
2. Тип `type <id>Rules struct{ ClassicRules }` и переопределить только нужные методы `Rules` (таблица ниже).
3. `type <id> struct{}` с `Info() Info` (`ID` латиницей и дефисом, `Name` по-русски, `Short` одно предложение правил) и `New(o Options) (State, error)`; для обычного хода-одним-действием: `return NewGame(<id>Rules{}, o)`. Если у вида есть настройки из лобби, добавить `CheckOptions(o *Options) error` (проверить `o.Params`, подставить значения по умолчанию).
4. `func init() { Register(<id>{}) }`.
5. Тест рядом (`<id>_test.go`), по образцу `extension_test.go`: расстановка, особые ходы, конец партии, повтор `Replay`.

**Хуки `Rules`** (все необязательны; `ClassicRules` отвечает по-классически; вид встраивает `ClassicRules` и пишет только своё; базовый ответ доступен как `r.ClassicRules.Method(...)`; ВАЖНО: методы `ClassicRules` не вызывают переопределённые методы вида, поэтому в вашем `Check` и `Result` не рассчитывайте, что базовая версия увидит ваши правки; `ClassicResult(g)` вызывает `g.Rules().Check`, то есть ваш `Check`, а не базовый)

| Нужда | Хук |
|---|---|
| (а) другая расстановка, случайный старт | `Start(o Options) (*Position, error)`: `ParseFEN(...)` или собрать `EmptyPosition()` вручную; случайность из `o.Rand()` |
| (б) правила взятия, побочные эффекты хода (взрывы) | `CanCapture(p, mv, victim) bool`; `AfterMove(next, info MoveInfo)` (после хода и передачи очереди; `info` знает, кто, чем, кого и где взял); после правок вызвать `next.FixCastling()` |
| (в) особые условия победы | `Result(g *Game) (result, reason string, over bool)`; по умолчанию `ClassicResult(g)` (в конце своей версии позовите её) |
| (г) нет шаха, король берётся | `Check` всегда `false` (база отбрасывает ходы, после которых `Check(next, ходивший)` истинно), `CastleSafe` всегда `true`, `Result` по отсутствию короля (`p.KingSq(side) == NoSq`) |
| (д) очередь из нескольких действий | не хук: свой `State` поверх `*Game` (`g.Moves()`, `g.Play(mv)`, `g.Edit(func(p *Position))`, `g.SetLast`, `g.Finish`, `g.Judge`); образец `twice` в `extension_test.go`; `Turn()` меняется только когда очередь действительно переходит |
| (е) высадки из резерва | `ExtraMoves(p) []Move` (ходы высадки `Move{From: NoSq, To: sq, Drop: kind, Rook: NoSq}`), `AfterMove` кладёт взятое в `next.Pocket[info.Side][kind]`, `Extra` отдаёт резерв сайту; база сама ставит фигуру и уменьшает резерв, а фильтр шаха применяется и к высадкам |
| (ж) рокировка | `Start` задаёт права (`Position.Castle`, из X-FEN/Shredder-FEN), `CastleAsKingTakesRook() bool`, `CastleSafe`; рокировка в базе общая (правила Фишера, включает классическую) |
| (з) скрытая информация | `Redact(g, viewer, *View)` убирает лишнее из `board`, `legal`, `last`, `check`, `extra`; `Extra(g, viewer)` отдаёт данные вида; список ходов скрывает `MoveRedactor` на `State` |
| пешки | `PawnDoubleStep(p, from) (allowed, setsEP bool)` (Орда: пешки с первой горизонтали идут на две клетки, но без взятия на проходе) |
| запись хода, время | `Notation(g, mv, legal, next) string` (по умолчанию `SAN`), `Timeout(g, loser) string` |

#### 5.F.2. Сервер `vplay` (готов)

Пакет `backend/internal/vplay` по образцу `play`, к `play` и `engine` не прикасается (берёт у `play` только тип `TimeControl`). Подключён в `backend/cmd/server/main.go` (`vplay.New(vplay.Config{Store: db, User: accounts.UserFromRequest})`, маршруты `/api/variants` и `/api/variants/`). Файлы: `game.go` (партия: часы, действия, ничья, реванш, чат, снимок, сохранение), `hub.go` (HTTP, WebSocket, сохранение, janitor), `seek.go` (быстрая игра). Хранение: таблица `variant_games` (миграция `0018_variant_games.sql`, `store/variantgames.go`); слияние аккаунтов и удаление аккаунта учитывают её.

**Запросы** (все под входом: гость подходит; зритель читает без входа):

- `GET /api/variants` -> `{variants: [{id, name, short, hidden}]}` (что знает сервер).
- `POST /api/variants/games` `{variant, color: white|black|random, timeMs, incMs, options?}` -> `201 {id}`. `timeMs` 0 (без часов) или от 10 с до 3 ч, `incMs` от 0 до 60 с. `options` проходят через `variants.Prepare` (`OptionsChecker.CheckOptions`; у вида без него `options` должны быть пустыми, иначе 400). Сид сервер выдаёт сам. До 5 неотвеченных приглашений на человека.
- `GET /api/variants/games/{id}` -> снимок `{type:"state", game, you}` (то же, что присылает сокет; у каждого зрителя свой). `POST .../join` -> снимок (409, если места нет). `GET /api/variants/games` -> `{items: [{id, variant, variantName, status, result, termination, white, black, tc, plies, updated, you}]}` (мои начатые).
- Быстрая игра (не рейтинговая): `POST /api/variants/seek` `{variant, baseMs, incMs, options?}`, `GET`, `DELETE` на тот же адрес. Ответ `{status: "none"|"waiting"|"found", id?, waited?, count?}`. Пара: вид, часы и `options` совпали; второй пришедший сразу создаёт партию с жеребьёвкой цвета, ожидающему `found` отдаёт его следующий `GET` (клиент опрашивает раз в секунду; без опроса 20 с запрос сбрасывается; найденная пара повторяется повторному опросу 10 с). Окна рейтинга нет.
- **WebSocket** `GET /api/variants/games/{id}/ws`. Клиент -> сервер: `{type:"move", action}` (одно действие вида; «move» для любого действия, в том числе высадки и утки), `{type:"resign"}`, `{type:"draw"}` (предложить или принять), `{type:"drawDecline"}`, `{type:"abort"}`, `{type:"rematch"}`, `{type:"chat", text}`. Сервер -> клиент: `{type:"state", game, you}` целиком после каждого изменения и `{type:"error", error}` + свежий снимок при отказе. Лимиты как у `play`: 4 КиБ, 20 подряд и 5 в секунду, проверка `Origin`, пинг 25 с, медленный клиент отключается.

**Снимок `game`:** `{id, variant, variantName, params?, status: waiting|playing|ended|aborted, result?, termination?, white, black ({id,name,avatar}), tc:{baseMs,incMs}, turn, position: <variants.View для этого зрителя>, moves: [{side, action, san}], clock?: {whiteMs, blackMs, running, serverNow}, firstMoveBy?, drawOffer?, rematch?: {offer, id}, presence: {white, black, watching}, chat?, created}`. `params` это выбор из лобби (сид не отдаётся). `moves` пропущен через `MoveRedactor`, если он есть у `State`; `position.legal` есть только у того, чей ход, и только пока партия идёт. `termination` это либо причина, которую вернул `State.Over()` (`checkmate`, `king-captured`, ...), либо `resign`, `timeout`, `agreement`, `aborted`, `no-first-move`, `expired`.

**Часы.** Время ведёт сервер; часы стоят, пока оба не прошли по одной очереди (`turnsDone >= 2`, очередь = смена значения `State.Turn()`); на первую очередь каждой стороне даётся 60 с, иначе партия отменяется без результата. Часы переходят и добавка за ход даётся, только когда `Turn()` сменился (в очереди из нескольких действий часы одной стороны идут через все её действия). Флажок: действие после падения отклоняется, партия кончается `timeout`; итог берётся у `Timeouter.Timeout(loser)`, если `State` его реализует (`*variants.Game` реализует: против голого короля ничья), иначе проигрывает упавший. Ничью можно предлагать после двух очередей; «Отменить» до двух очередей.

**Окончание не от правил.** Сдача, флажок, ничья по согласию: сервер зовёт `Finisher.Finish(result, reason)` у `State` (`*variants.Game` реализует), поэтому вид со скрытой информацией открывает всё и перестаёт выдавать ходы.

**Сохранение.** Документ `saved` (`variant`, `options` с сидом, действия с записью, часы, очередь, предложения, чат). Партия поднимается из базы при первом обращении повтором действий (`variants.Replay`), часы продолжают идти. Из памяти уходит через 10 минут после конца без зрителей. Приглашение живёт сутки.

**Реванш:** обоюдное согласие, цвета меняются, вид и выбор из лобби те же, сид новый.

**Тесты:** `go test -race ./backend/internal/vplay/` (около 2 с, без MySQL, в памяти): партия по сокетам до мата, права игроков и зрителя, ошибки и истинный снимок, создание и проверки, сдача, ничья, отмена, реванш, чат, перезапуск (поднятие из базы и продолжение), чужой `Origin`, часы на поддельных часах (старт, добавка, флажок, таймер, нет первого хода, флажок против голого короля), очередь из двух действий (часы переходят только при смене очереди), скрытая информация (каждый видит своё, зритель ничего, после сдачи всё открыто), настройки и сид, быстрая игра (пара, разные часы и виды, отмена, срок, `options` входят в ключ пары). Мини-виды этих тестов (`t-twice`, `t-fog`, `t-opts`) лежат в `game_test.go`: образец, как `State` подключается к серверу.

**Для Bughouse (E):** `vplay` рассчитан на два места (белые и чёрные). Четыре игрока и две доски потребуют правки `vplay` (места, часы у каждого игрока); договоритесь, что правите минимально и не ломаете тесты выше.

**Решения по правилам (как на Lichess, отклонения отмечены).**
- *Атомные.* Центр взрыва: клетка, куда встала бьющая фигура (и при взятии на проходе). Исчезают бьющая, взятая и все не-пешки на восьми соседних клетках; пешки рядом остаются, бьющая и взятая пешки исчезают. Король не бьёт. Ход, взрывающий своего короля, нелегален; ход, взрывающий чужого, легален и выигрывает даже при шахе (`Check` для стороны без короля истинен, для хода, после которого нет короля соперника, ложен). Короли рядом: шаха нет ни у кого, короли могут вставать рядом. Мат и пат как обычно (пат ничья). В записи хода после взорванного короля нет `+`/`#`. Конец взрывом: причина `king-exploded`. Недостаточный материал (`atomicCanWin`, осторожное прочтение Lichess): сторона не может выиграть без фигур, кроме короля; пока у соперника есть фигуры, шанс взорвать их рядом с королём есть всегда, кроме окончания из одних слонов, где слоны разных цветов клеток друг друга не бьют; против голого короля нужен ферзь или пешка, либо две и более из коня, слона, ладьи (но не слоны одного цвета). Ничья, если не может выиграть ни одна сторона. Флажок: ничья, если у соперника выиграть нельзя.
  - *Отклонения:* путь рокировки проверяется без боя вражеского короля (он не бьёт); взятие с превращением предлагается только ферзём (фигура взрывается сразу), для этого в `Legal` отбрасываются `b7a8n` и т. п., а на доске в `Board.jsx` добавлена одна строка: если превращение с единственным вариантом, пикер не показывается (`letters.length === 1`).
  - *Показ взрыва:* `atomicGame` (обёртка над `*Game`) помнит последний взрыв и отдаёт `extra.blast = {center, squares, pieces}` (клетка, где исчезла фигура, и код исчезнувшей фигуры); восстанавливается повтором действий.
- *Царь горы.* Король на d4, e4, d5 или e5 выигрывает сразу (проверяется раньше мата, пата и ничьих); обычный мат и всё остальное классическое. На клетку под боем король не может встать, это обычный ход под шах. Причина `king-of-the-hill`.
- *Орда.* Расстановка Lichess `rnbqkbnr/pppppppp/8/1PP2PP1/PPPPPPPP/PPPPPPPP/PPPPPPPP/PPPPPPPP w kq - 0 1` (36 пешек у белых, рокировка только у чёрных). Белые пешки с первой горизонтали идут на две клетки (оба поля свободны), след на проходе не оставляют; со второй как обычно, с проходом. Белым не бывает шаха, мат только чёрному королю. Чёрные побеждают, взяв все белые фигуры (причина `horde-destroyed`). Нет ходов у белых или у чёрных без шаха: пат. Ничьей по недостатку материала нет вовсе (чёрные всегда могут съесть остаток орды, как у Lichess); есть 50 ходов и повторение. *Отклонение:* флажок чёрных даёт белым победу, если они вообще могут поставить мат (пешка, ладья, ферзь, две лёгкие фигуры, или одна лёгкая, если у чёрных есть ещё фигуры, кроме короля), иначе ничья; флажок белых всегда победа чёрных. Таблица Lichess для таких окончаний длиннее.

**Сайт** (`web/src/variants/<id>/`): `atomic/` (`index.jsx`, `blast.js` + тест, `atomic.css`): подсветка клеток взрыва через `boardProps.squareClasses` (центр ярче, красный тон `--danger-rgb`), карточка «Последний взрыв» в слоте `Side` (центр, кто исчез), `captured: false`, текст конца «Король взорван». `kingofthehill/` (`index.jsx`, `hill.js` + тест, `hill.css`): четыре центральные клетки подсвечены всегда (`--warn-rgb`), карточка «До центра» (сколько ходов королю до горы, считается по доске). `horde/` (`index.jsx`, `horde.js` + тест, `horde.css`): карточка с числом оставшихся белых фигур (`extra.horde`) и подсказкой, что нужно каждой стороне, `captured: false`, текст «Орда уничтожена». Значки `atomic`, `hill`, `horde` добавлены в `ui/Icon.jsx` (только добавление), порядок в меню 20, 30, 40. Цвета только токены.

### Утиные и Dice chess (C)

**Статус (2026-10-21):** оба вида готовы и проверены вживую. Go: `variants/duck.go`, `dice.go`, `turns.go` (интерфейс `TurnCounter`), тесты `duck_test.go`, `dice_test.go`, `vplay/dice_test.go`. **Утиные (id `duck`).** Оба хода очереди принадлежат одной стороне; `State` оборачивает `*Game`. После хода фигурой `Game` передаёт ход другой стороне, но `State.Turn()` возвращает ходившего, пока не поставлена утка (флаг `mid`), поэтому часы идут через оба действия. Действия: ход фигурой (`e2e4`, `e7e8q`, `e1g1`), затем `@e5`. Запись: `Nf3` и `@e5` двумя записями одной стороны; список ходов склеивает их в одну ячейку «Nf3 @e5». `View.Extra = {step: "move"|"duck", duck: "e5"|""}`, в шаге утки `legal` = `@<клетка>` для всех свободных клеток, кроме той, где утка стоит.
Решения по правилам:
- Утки в начале нет; белые ставят её после первого хода на любую свободную клетку. Дальше утка уходит на другую свободную клетку (не на ту же).
- Шаха нет: `Check` всегда ложен, король ходит под бой, партия кончается взятием короля сразу (шаг утки после взятия не нужен), причина `king-captured`.
- У кого к началу своей очереди нет ходов фигурой, тот выигрывает (причина `no-moves`, на сайте текст про это). Проверка идёт после постановки утки соперником.
- Рокировка: правила без шаха: клетки между королём, ладьёй и их конечными полями свободны (утка тоже блокирует), права не потеряны; атакованные клетки не важны (`CastleSafe` всегда истинно).
- Утка стена: фигуры и пешки на неё не ходят и через неё не проходят (конь перепрыгивает, на её клетку не встаёт), взять её нельзя. Взятие на проходе возможно, пока утка не стоит на клетке взятия.
- Ничья по правилу 50 ходов и троекратному повторению остаётся (утка входит в позицию; на полуготовой позиции между ходом и уткой повторение не проверяется). Недостатка материала нет (голый король может взять короля). Флажок проигрывает всегда.
- Утка на доске: фигура `xD`, на сайте рисуется SVG (`pieces` определения; цвета только токены: тёмная тема и светлая). Шаг утки: подсвечены свободные клетки (`extraDots`), в карточке справа «Ход фигурой / Утка на свободное поле», подсказка «Поставьте утку…». Если включено «подтверждать ход», первый клик отмечает клетку (`hint`), в карточке кнопка «Поставить на e5».

**Dice chess (id `dice`).** Очередь из трёх бросков. Состояние хранит свой генератор из `Options.Rand()` (один раз при создании) и бросает кубик сразу после предыдущего действия: тип выпавшей фигуры = `Kind(1+rng.Intn(6))` (1 пешка … 6 король). Действия только ходы фигурой выпавшего типа (`e2e4`, рокировка `e1g1` при кубике короля). Ход с пропуском не отдельное действие: сервер сам бросает следующий кубик, пока не выпадет тип, которым есть ход.
Решения:
- Нет хода выпавшим типом: этот из трёх ходов пропущен, бросается следующий. Если все три пропущены, очередь целиком переходит сопернику, и так пока кто-то не получит ход (это бывает и до первого хода: 4 из 6 граней в начальной позиции не имеют ходов, очередь белых пропускается целиком в трети партий, тогда первым ходит чёрный; записано в первой записи «Белые: пропуск хода (слон, ладья, ферзь)»).
- Часы: `Turn()` = тот, кто действует; один ход `Apply` может передать очередь дважды подряд (пропущенная очередь соперника), и `Turn()` тогда тот же. Добавлен маленький аддитивный хук: интерфейс `variants.TurnCounter{TurnsPassed() int}` (файл `turns.go`) и в `vplay.Game.Act` счёт `passed` (разница `TurnsPassed` до и после; для состояний без интерфейса прежнее правило «Turn изменился»). Время ходившего списывается один раз, добавка один раз, пропущенная очередь времени не стоит и надбавки не даёт, `turnsDone += passed` (две очереди «сыграны», часы стартуют правильно). Тест `vplay/dice_test.go` проверяет это на 12 партиях с реальным кубиком.
- Правило «нет ходов» базы (`Legal()` пустой = пат/мат) на Dice не действует: `Game.Result` сторона не смотрит на кубик, `Game.Legal()` не фильтруется по нему, фильтр по типу сделан в `State` (`Legal()` у `diceState`). Пат только если у стороны нет ни одного хода никакой фигурой: ничья `stalemate` (иначе зацикливание).
- Шаха нет, партия кончается взятием короля, даже посреди очереди. Рокировка ход короля, поля под боем не важны.
- Правило 50 ходов считает ходы (150 ходов без взятия и хода пешки = ничья `fifty-moves`); повторения нет (кубик не входит в позицию). Недостатка материала нет. Флажок проигрывает.
- Определённость: кубики зависят только от сида и числа бросков; партия поднимается из базы повтором действий, броски те же (проверено перезапуском сервера вживую и тестами `TestDiceSameSeedSameDice`, `TestDiceGameIsRestoredWithItsDice`). Сид клиенту не отдаётся.
- Запись: каждое действие `P: e2e4`, `N: g1f3`; пропуски дописываются к записи действия, после которого случились (`P: e2e4 | N: g1f3 | пропуск (слон)`), пропуски перед первым ходом очереди идут префиксом первой записи, целиком потерянная очередь пишется «Чёрные: пропуск хода (конь, конь, король)». Список ходов склеивает записи одной очереди через ` | ` (новое поле определения `moveSep`, правка одной строки в `VariantRoom.jsx`).
- `View.Extra = {step, of: 3, die, rolls: [{die, result: moved|skipped|now}], turns, lost?: {side, dice}}`. На сайте над доской полоса из трёх граней кубика (SVG, пипсы; текущая с зелёной рамкой, сыгранные и пропущенные приглушены), «Ход 2 из 3», «Выпал конь: ходите конём» (сопернику «Белые: выпал конь»), сообщение о потерянной очереди; фигуры, которыми можно ходить, обведены на доске (`squareClasses`, класс `dice-movable`).

**Что поправлено в общих файлах** (на случай конфликта): `ui/Icon.jsx` (значки `duck`, `dice`, дописаны в конец списка), `variants/VariantRoom.jsx` (одна строка: `join(def.moveSep ?? " ")` в списке ходов), `vplay/game.go` (`turnsPassed`, подсчёт `passed` в `Act`), новый `variants/turns.go`.

**Тесты.** Go: `go test -race ./backend/internal/variants/ -run "Duck|Dice"` и `./backend/internal/vplay/ -run Dice` (оба видны в общем прогоне). Duck: ход и утка, утка стена, нельзя на фигуру и на своё поле, линия, взятие короля, король идёт под бой, рокировка (через атаку да, через утку нет), нет ходов, флажок, запись, 120 случайных партий с повтором. Dice: только выпавший тип ходит, 3 хода в очереди, сид и повтор, рокировка, конец при взятии короля, целиком пропущенная очередь (счёт передач, запись, `lost`), пропуски в записи, пат, честность граней (6000 сидов: каждая грань 1/6 +-20 %), 100 случайных партий с повтором. Сайт: `npm test` (`duck.test.js`, `dice.test.js`).

**Проверено вживую (Edge, две сессии, порт 8095, сценарии `duck.mjs`, `dice.mjs`, `duck2.mjs` в папке вне проекта):** Duck: создание по ссылке с часами 3+2, e4 и шаг утки (подсказка, точки на свободных полях, клик по фигуре игнорируется), утка на e5 у обоих, запись «e4 @e5», e7-e5 через утку отказано, нельзя поставить утку на её же поле, утка переехала на a3, часы идут только после двух очередей, Qh5 Qxf7 Qxe8 взятие короля, итог «Белые победили взятием короля», перезагрузка, без ошибок в консоли, 1440 и 390 px без горизонтальной прокрутки, светлая тема. Dice: партия на 4-9 очередей с пропусками, потерянными очередями (в том числе первой очереди белых), превращением, перезагрузкой страницы посреди очереди (кубик тот же и мой ход), перезапуском сервера посреди очереди (кубики, ходы и запись те же), 1440 и 390 px, светлая тема, без ошибок (кроме отказа соединения во время перезапуска).

**Не проверено / не сделано.** Сенсорный экран. Звук ходов: для записей видов он выбирается по `x` в записи (у Dice «P: e2e4» без `x`, взятие звучит как обычный ход). Подтверждение утки при включённом «подтверждать ход» проверено только тестом логики (`duck.test.js`), не глазами. Утка и рокировка по правилам другого сайта могут отличаться (записано выше). При общем прогоне `go test ./backend/...` в момент сдачи падали не мои тесты: `store` (`gap between migration 18 and 23`: номера 0019-0022 пропущены, а загрузчик миграций требует непрерывности; кому нужна 0023 (E), пусть переименует в свободный номер или добавит пустые 0019-0022) и `vplay` Bughouse (E, в работе).

### Туман войны (D)

**Статус (2026-10-21):** готов, id `fog`. Go: `backend/internal/variants/fog.go` (+ `fog_test.go`), тест сервера `backend/internal/vplay/fog_test.go`. Сайт: `web/src/variants/fog/` (`index.jsx`, `fogview.js` + `fog.test.js`, `fog.css`), значок `fog` в `ui/Icon.jsx`. Миграция не нужна (0022 пропущена). Общие файлы тронуты дважды: `Icon.jsx` (добавлен значок) и `vplay/game.go` (одна строка, см. «Патч основы»).

**Правила (Chess.com).** Шаха и мата нет: `Check` всегда `false`, король может встать под бой, ходы допустимы все псевдолегальные. Рокировка обычная, но без проверки шаха (`CastleSafe` всегда `true`). Взятие на проходе и превращение обычные. Партия кончается взятием короля (`Result`: нет короля у стороны -> победа другой, причина `king-captured`). Сторона без допустимых ходов даёт ничью (`stalemate`). Автоматических ничьих нет (повторение, 50 ходов, недостаток материала): они выдавали бы скрытое; остаются ничья по согласию, сдача, флажок. Флажок: выигрывает тот, у кого осталось время, даже против голого короля (любая фигура может взять короля; `Timeout` переопределён).

**Что видит игрок** (одна функция `fogVisible`): свои фигуры; конечная клетка каждого хода своей стороны (слайдер доходит до первой фигуры и видит её, дальше туман); клетка пешки, взятой на проходе; поле впереди пешки на одно и второе с начальной позиции, если первое пусто, и стоит там кто угодно (заблокированная пешка видит блокиратора; **решение по пешке:** диагонали пешки видны только как поля взятия, то есть когда на них стоит чужая фигура, пустая диагональ в тумане); клетка, где фигура соперника только что взяла вашу (вы видите, чем вас взяли), пока вы не сходили. Видимость считается и в ход соперника (поля, куда ваши фигуры могли бы сходить, с `Turn` вашей стороны и без поля взятия на проходе).

**Утечки: что закрыто.**
- `board`: только видимые клетки. `legal`: только ходящему; каждая конечная клетка допустимого хода видима по построению, так что список ничего не раскрывает (ход через скрытую фигуру просто отсутствует, ход со взятием скрытой допустим: цель видна как поле взятия). Тест проверяет `legal ⊆ видимое`.
- `last`: ход соперника показывается только видимыми из двух клеток (одна клетка или пусто, но не обе, чтобы не выдать скрытую цель/начало); свой ход виден целиком. Клиент рисует `from == to` для одной клетки.
- `check`: пусто. `extra`: `{"fog": [скрытые клетки]}` (после конца партии `extra` нет).
- Список ходов (`RedactMoves` на `State`): свои ходы целиком; ход соперника без поля `action` всегда; текст `«…»`, если его конечная клетка не была вам видна сразу после хода, иначе короткая запись «фигура, x, цель» без начальной клетки и без уточнений (`Nxe4`, `xd5`, `O-O`, `e8=Q`; взятие вашей фигуры всегда видно, потому что клетка вскрывается). Зритель: все ходы `«…»`.
- **Зритель** во время партии не видит ничего: `board` пуст, `extra.fog` = все 64 клетки, на сайте доска закрыта целиком и написано «Зрители видят доску после конца партии». После конца партии доска и ходы открыты всем. Чата и сообщений о взятии сервер сам не пишет (чат только игроков). В `vplay` нет PGN для видов; `GET /api/variants/games` отдаёт только число ходов и результат (результат есть лишь после конца); база хранит действия целиком (это внутреннее, клиенту не уходит).
- После конца партии не от правил (сдача, флажок, ничья, **отмена**) `Finish` открывает всё и ходы.

**Патч основы (описан для журнала).** `vplay/game.go`, `finish()`: `Finisher.Finish` теперь зовётся и для отменённой партии (`StatusAborted`), раньше только для `StatusEnded`; иначе отменённая в туман партия оставалась бы закрытой у обоих. Остальные виды не меняются (у `Game.Finish` для отмены побочных эффектов нет). Других хуков не понадобилось: скрытие сделано на `State` (`fogGameState` оборачивает `*Game`, хранит по каждому ходу «видела ли соперница цель»), как и в образце `fogState`; `Rules.Redact` не использован, потому что ему не хватало памяти о взятии (оно решает, что показывать, пока ходящий не ответил).

**Тесты.** Go (`go test -race ./backend/internal/variants/ -run Fog -v`): правила (нет шаха, взятие короля, рокировка через бой, на проходе, превращение), стартовая позиция (белые видят 1-4 горизонтали), зрение пешки, слайдеры, ход вне очереди, `last`, запись ходов, всё открыто в конце и после `Finish`, зритель, повтор `Replay` (снимок побайтово). Главные: `TestFogNoLeaksInRandomGames` (40 партий по 140 полуходов, для каждой позиции и обоих игроков: множество видимых клеток равно независимому оракулу из чистой геометрии, в снимке ровно фигуры оракула, в сериализованном тексте нет имён скрытых клеток, `legal` и `last` видимы, список ходов не содержит начальных клеток), `TestFogShownMovesWereInView` (показанный ход стоит на видимой клетке) и **`TestFogNoninterference`** (в 4664 позициях подменяем скрытые чужие фигуры: убираем, ставим, меняем; снимок игрока не меняется ни на байт; исключены лишь диагонали своих пешек и клетки рядом с ними, их показ по правилу зависит от присутствия фигуры). Проверено, что тесты ловят утечку (временно показывал лишние клетки: падают 8 тестов). Сервер (`go test -race ./backend/internal/vplay/`, файл `fog_test.go`): партия по сокетам до взятия короля, у каждого игрока и зрителя читаются сырые кадры (нет чужих действий, чужих фигур на скрытых клетках, зритель видит пустую доску), сдача и отмена открывают всё, перезапуск сервера поднимает партию с тем же туманом. Сайт: `npm test` (`fog.test.js`).

**Проверено вживую** (Edge, три сессии `createBrowserContext`, сервер 8096, сценарий `scratchpad/fogD/fog.js`): каталог со значком, лобби с правилами, создание и вход по ссылке, партия 1.e4 f6 2.Qh5 a6 3.Qxe8 (взятие короля); после каждого хода DOM доски совпадает со снимком (те же фигуры, на закрытых клетках нет фигур и нет атрибутов `title`, `aria-*`, `data-*` кроме `data-square`), в сырых WebSocket-кадрах чёрных нет белого хода `e2e4` и белых фигур на закрытых клетках; список ходов («…» там, где не видели), зритель (пустая закрытая доска, «Зрители видят доску после конца партии», кадры без фигур и действий), перезагрузка страницы посреди партии у обоих (та же картина), 1440 и 390 px (без горизонтальной прокрутки), светлая тема, итоговая карточка («Белые победили взятием короля»), после конца открыты 31 фигура и весь список, зритель видит доску после конца, партия в «Партиях» с названием вида.

### Crazyhouse и Bughouse (E)

#### E.1. Crazyhouse (готово, 2026-10-21)

**Правила** (`backend/internal/variants/crazyhouse.go`, общее с Bughouse в `pockets.go`; вид `crazyhouse`). Хуки: `ExtraMoves` (высадки `DropMoves`: любая фигура резерва на любое пустое поле, пешка не на 1-ю и 8-ю горизонтали; пешку на 2-й горизонтали можно двинуть на две клетки, как на Lichess), `AfterMove` (взятое кладётся в резерв взявшего; превращённая фигура и взятие на проходе: `PocketKind`), `Extra` (`PocketExtra`: `{white:{Q:1,P:2}, black:{...}, promoted:["a8"]}`), `Result`, `Timeout`. **Как устроено и почему (выбранный подход).** Предложенный в задаче подход оказался лучшим, поэтому правил движка не трогал (в `engine/` Chess960 нет: `grep` по «960» и «shredder» находит только константы магических чисел и комментарий книги; движок знает рокировку только классическую e1g1/e1c1). Рассмотренные альтернативы: (а) научить движок рокировке Фишера: правка ядра, поиска и NNUE-признаков ради одной ветки сайта, риск для всех остальных тестов; (б) переводить рокировку 960 в обычный ход «король на g1»: неверно, когда король стоит на g1 или ладья мешает; (в) разбор партии по позициям из `variants`: выбрано.
- Позиции и ходы даёт `variants` (`analysis.NewVariantGame`: повтор действий партии, перед каждым ходом FEN с обнулёнными правами рокировки, число легальных ходов ходящего, SAN из записи `variants`, признак рокировки: король берёт свою ладью). Каждая позиция уходит в движок как есть: расстановка нестандартная, но поиск и NNUE работают с любой.
- Потеря хода считается как всегда: лучшая оценка позиции до хода против оценки позиции после сыгранного хода (сыгранный ход движком не проверяется, позицию после него даёт доска `variants`). Для хода, который движок не умеет сделать (рокировка), нет «лучшего хода» для сравнения по тексту; если потеря нулевая, ход считается «лучшим».
- Код разбора (`analysis.go`) разделён на `Analyze` (PGN, строит `timeline`) и `review(timeline)` (поиск и оценка ходов); PGN-разбор тем же кодом, тесты `analysis` прежние и проходят. Новое: `analysis/variant.go` (`NewVariantGame`, `AnalyzeVariant`, `SupportsVariant`), поле `Report.Variant` (`"chess960"`, у обычных разборов пусто), `GameInfo.Variant`.
- API: `POST /api/analyses/variant {"game": "<id партии>", "depth": 0}` в той же очереди; ответ `202 {id}`, дальше обычный `GET /api/analyses/{id}`. Принимает только окончившиеся партии (`status = ended`, иначе 409; нет ходов, не Chess960, неизвестная партия: 400/404). Номер разбора выводится из партии и глубины (хэш), поэтому повторное нажатие (хоть соперником, хоть после перезагрузки или рестарта сервера) находит тот же разбор, а не считает заново. Хозяин в «Мои партии»: тот, кто нажал первым. Источник партии: `vplay.Hub.ReviewGame` (из памяти или базы; сид остаётся на сервере), подключён в `cmd/server/main.go` через `api.Config.VariantGame`.
- Сайт: `variants/api.js` (`createReview`), `VariantRoom.jsx` (кнопка и `onReview` у карточки итога для определений с `review: true`, текст `reviewHint`; слот `boardLocked` см. ниже), `chess960/index.jsx` (`review: true`). На странице разбора (`review/ReviewView.jsx`, точечно, один абзац) под строкой «Chess960» мелкое пояснение: теории нет, рокировку движок не видит.

**Ограничения (честно).**
1. Пока рокировка возможна, движок про неё не знает: лучшим ходом он её никогда не назовёт, оценка позиции «без рокировки» может быть чуть ниже настоящей. Сыгранная рокировка оценивается по позиции после неё как любой ход. Пояснение есть на странице разбора и в карточке партии.
2. Ходы после рокировки разбираются от позиции без прав рокировки (они уже потеряны в партии).
3. Повторение позиции считает движок по позициям без прав: позиция, повторённая только после потери прав, может быть засчитана раньше; в реальной партии это очень редкий случай.
4. Линия разбора и «своя ветка» берут позиции без прав рокировки (в FEN поле `-`), поэтому ветка на рокировке 960 не ломается: рокировка в ней просто недоступна. «Копировать PGN» на странице разбора пишет начальную позицию без прав, а ходы «O-O» из партии: такой PGN другой программой на рокировке не воспроизведётся (не правил, это работа страницы разбора).
5. У ходов рокировки в отчёте `uci` записан как «король откуда куда встал» (`e1g1`, при неподвижном короле `g1g1`), чтобы страница подсвечивала клетки короля и ставила значок на короля; настоящее действие партии (`e1h1`) в отчёте не хранится.
6. Только Chess960: у остальных видов правила другие (взрывы, утка, туман и т. д.), для них разбор не делается.

**Тесты.** `go test -race ./backend/internal/analysis/ -run "Variant|Chess960"` (`variant_test.go`): рокировки всех четырёх видов (король остаётся на месте, король и ладья меняются местами, короткая, длинная; играются случайные партии по нескольким расстановкам, рокировка берётся при каждой возможности), SAN «O-O»/«O-O-O», движок не называет рокировку лучшим ходом, мат (последняя позиция терминальная, ход «лучший», зевок перед ним), число ходов отчёта равно числу ходов партии, нет книжных пометок и дебюта, точность 0..100, цвета ходов, детерминизм (Depth 3, один и три потока дают одинаковый JSON), круг JSON, отказы (не Chess960, нелегальный ход). `go test -race ./backend/internal/api/ -run Variant` (`variant_test.go`): весь путь через очередь и хранилище, «O-O» в отчёте, второй щелчок находит тот же разбор, рестарт сервера отдаёт его из хранилища и новый щелчок не создаёт второй, отказы (нет хаба, плохой JSON, чужой вид, идущая партия, нет ходов, неизвестная партия, нелегальный ход). `go test -race ./backend/internal/vplay/ -run ReviewGame` (источник партии).

**Проверено вживую** (Edge, две сессии, сервер 8098, расстановка 518): партия e4 e5 Nf3 Nc6 Bc4 Nf6, рокировка белых кликом король-ладья (e1, h1), Be7, d3, рокировка чёрных (e8, h8), сдача белых; у обоих итоговая карточка с кнопкой «Смотреть отчёт» и пояснением; у второго игрока после закрытия карточки кнопка «Разбор партии» в колонке; разбор открылся (`#review/911b9a6969ec3f52`, список ходов «O-O» «Be7» «d3» «O-O», подпись «Chess960, расстановка 518», пояснение про рокировку), перезагрузка страницы открыла тот же разбор, первый игрок нажал «Разбор партии» и получил тот же номер; на 1440 и 390 px без горизонтальной прокрутки, ошибок консоли нет. #### 2. Dice chess: три кубика сразу

**Что изменено (правило).** В начале очереди сервер бросает **три** кубика сразу, они все в каждом снимке (у обоих игроков и у зрителя); раньше бросался один кубик перед каждым ходом. Решения по деталям:
1. Все три броска делает сервер из того же генератора `Options.Rand()` (три броска подряд в начале каждой очереди, порядок фиксирован, сид клиенту не отдаётся), повтор действий даёт те же броски (тесты `TestDiceSameSeedSameDice` на любой точке партии, `TestDiceGameIsRestoredWithItsDice`, `TestDiceSnapshotShowsAllThreeAndSurvivesARestore`).
2. Ходить можно любой фигурой того типа, у которого есть неиспользованный кубик, в любом порядке. Одинаковые типы взаимозаменяемы: сервер сам списывает первый неиспользованный кубик этого типа. Действие остаётся ходом фигурой (`e2e4`).
3. ~~Тип без хода не сгорает~~ **Заменено (см. «Поправка после замечаний автора» ниже):** кубик, фигурой которого нечем ходить, пропускается сразу и окончательно; то же после каждого хода для каждого оставшегося кубика. Если остались только пропущенные, очередь заканчивается; в записи «пропуск (слон, ферзь)».
4. Очередь, в которой с самого начала нечем ходить ни одним из трёх типов, целиком теряется и переходит сопернику, у него сразу новые три кубика (запись «Чёрные: пропуск хода (конь, конь, король)», в снимке `extra.lost`); потерянная очередь перед первым ходом партии пишется префиксом первой записи. Пат (нет ни одного хода ни у какой фигуры) по-прежнему ничья.
5. Шаха нет, партия кончается взятием короля, 50 ходов (150 полуходов без взятия и хода пешки), часы без изменений (`TurnCounter`, `passed` в `vplay/game.go`; тесты часов `TestDiceSkippedTurnsKeepTheClockHonest` проходят без правок).
6. Бросок как отдельное действие сервера (`roll`) **не делал**: кубики известны с начала очереди, нажатие только раскрывает их ходящему (ничего скрывать нечем: расклад предопределён сидом, а соперник видит их сразу). Следствие, записанное как косметика: соперник видит три фигуры, как только очередь началась, а не после нажатия бросающего.

**Снимок (`View.Extra`)** теперь `{of: 3, dice: [{die: "P"|"N"|"B"|"R"|"Q"|"K", state: "free"|"used"|"skip"}], left, turns, lost?}` (раньше `{step, die, rolls}`). `free`: можно ходить; `used`: сыгран; `skip`: фигурой нечем ходить, пропущен окончательно. `legal` у ходящего включает ходы всех неиспользованных типов. Запись ходов как прежде (`P: e2e4 | N: g1f3`, пропуски после действия).

**Сайт** (`web/src/variants/dice/`: `dice.js` и тест, `index.jsx`, `dice.css`). В начале очереди у ходящего вместо кубиков крупная кнопка «Бросить кубики» (доска закрыта до нажатия: новый необязательный слот `boardLocked(ctx)` определения вида, одна правка в `VariantRoom.jsx`: `disabled={!myTurn || !!def.boardLocked?.(ctx)}`); по нажатию крупная анимация броска (см. «Поправку после замечаний автора» ниже), затем три грани с фигурами и названиями и подписями «можно ходить» / «нечем ходить, пропуск» / «сыграно», строка «Осталось ходов: 2 из 3.

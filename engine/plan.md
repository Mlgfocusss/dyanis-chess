## Как здесь принято работать (важно соблюдать)

- **Маленькие, независимо проверяемые шаги.** Не наслаивать несколько
  независимых изменений в один заход.
- **Силу игры меряет только матч (`cmd/match`)**, не число узлов и не
  тактический suite. Узлы (`cmd/profile`) отвечают только за скорость;
  тактический suite (`go test -v -run TestTacticalSuite ./internal/search`)
  — проверка, что ничего не сломано, а не термометр силы.
- **Порядок работы над изменением поиска/эвала:**
  1. `go build -o baseline.exe ./cmd/cli` ДО правки (или взять
     существующий `baseline.exe`, если он соответствует текущему коду);
  2. правка; `go vet ./internal/search`;
  3. `go build -o candidate.exe ./cmd/cli`;
  4. `.\match.exe -a candidate.exe -b baseline.exe -movetime=100
     -pairs=300 -concurrency=16 -elo0=0 -elo1=10 -openbook=assets/gm2001.bin`
     (≈ 7 минут на 100 мс; для 500 мс `-concurrency=8`; запускать
     в фоне, ноутбук не выключать);
  5. если SPRT не закрылся — вторая серия с `-seed=2` в тот же
     `"-carry=файл"` (кавычки обязательны в PowerShell 5.1 — иначе
     `-seed` молча теряется), итог считается по всем парам сразу;
     принимать, если нижняя граница 95%-интервала выше нуля. Интервал
     теперь по парам (пентаномиальный) — уже, чем у старых серий в этом
     файле, поэтому старые цифры «±15» и новые между собой напрямую не
     сравнивать;
  6. принято → `go test ./internal/search`, `baseline.exe` пересобрать
     из нового кода, описать в `TECHNICAL.md`; не принято → откат
     полностью, без остатка, запись сюда в «Реализовано, откачено».
- **Гипотеза может не подтвердиться — это нормальный исход, не провал.**
  Мёртвый код и неиспользуемые поля хуже чистого отката.
- **`go run` на Windows не всегда пересобирает надёжно** — для сравнения
  до/после всегда `go build -o что-то.exe`, потом запуск exe.
- **`go test -race` на Windows** требует cgo и настоящего C-компилятора
  (ставили `winget install BrechtSanders.WinLibs.POSIX.UCRT`, `bin` в
  `PATH`, `go env -w CGO_ENABLED=1`).
- **Фоновые команды с параметром `timeout` убиваются по его истечении** —
  для матчей (>10 минут) `timeout` не задавать.
- Тестов на `internal/eval` **сознательно нет** (кроме интеграционных
  `Evaluate()`) — решение автора проекта.
- Эвал автор уже много раз тюнил Texel'ом — новые термы эвала не
  предлагать без явной просьбы.
